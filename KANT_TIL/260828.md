  - dropout의 기본적인 동작은 전달되는 값의 일부를 0으로 만들어버리는 것이다.
  - 학습모드에서만 동작하며, 평가모드에서는 동작하지 않는다.
  - 파라미터가 많으면 학습 데이터의 세부 패턴을 쉽게 외울 수 있는데, 데이터가 충분하지 않거나 데이터에 비해서 모델이 너무 크면 train accuracy는 높아지지만 valid accuracy가 낮아지는 과적합 현상이 발생하게 된다.
  - dropout은 이러한 과적합 현상을 방지하기 위해서 일부 뉴런의 출력을 0으로 만들어버리는 것이다.
  - 일부 뉴런들이 꺼지기 때문에 특정한 뉴런에만 의존하지 않게되며, 학습할 때마다 조금씩 다른 모델로 학습하는 것 같은 효과를 볼 수 있고, 학습 모델을 외우지는 못하고 일반화 성능은 좋아진다.
  - dropout은 보통 활성화 함수의 뒤(다음 은닉층 직전)에 넣는다.
  - dropout은 `p`값을 통해서 각 뉴런이 0으로 바뀔 확률을 정할 수 있다.
  - 너무 높다면 많은 뉴런들이 비활성화되어 과소적합 현상이 발생할 수 있고, 너무 낮다면 과적합 완화의 효과를 많이 보지 못할 수 있다.
  - dropout을 했을 때 특정 뉴런들이 0이 된다는 것은 민감도가 줄어든다는 것이기 때문에 그만큼 살아있는 다른 뉴런들에 보정을 해서 민감도를 올려준다.
  - 이는 확률이 높을수록 강하게 보정하고, 낮을수록 조금만 보정한다.
  - 보통 Linear -> ReLU -> Dropout -> Linear 와 같은 형태로 사용된다.

  - 핵심은 이렇게 값을 바꾸지만 값들 사이의 상대적인 관계는 유지를 한다.
  - 값들이 바뀐다고 해도 A가 B보다 원래 컸다면 바뀐 후에도 여전히 A가 B보다 크다.
  - batchnorm을 사용하면 전체적인 weight가 작아지는 경향이 있긴 하지만 그게 무조건 그런 것은 아니다.
  - batchnorm은 1d, 2d, 3d가 있는데, 이는 텐서의 차원이 아니라 배치, 채널을 제외한 n개 만큼의 차원을 한 번에 계산을 하겠다는 의미이다.
  - batchnorm도 학습 모드와 평가 모드에서의 동작이 다른데, 학습 모드에서는 running statistics(`running_mean`, `running_var`)을 업데이트를 하고, 평가 모드에서는 학습 모드에서 만들어진 통계를 변화 없이 사용만 한다.
  - 그렇기 때문에 평가 모드를 선언하지 않고 평가를 진행하면 모델에 변화가 발생할 수 있다.
  - batchnorm은 MLP에서 활성화 함수 전에 사용된다.
  - Linear -> BatchNorm -> ReLU -> Linear와 같이 사용되며, dropout과 함께 사용되는 경우에는 Linear -> BatchNorm -> ReLU -> Dropout -> Linear의 구조를 가진다.
  - 물론 이러한 순서는 보통 이렇게 한다는 것이고 원한다면 순서를 아무렇게 섞을 수도 있다.

  - 모델은 기본적으로 epoch가 늘면 훈련 데이터에 적합하게 되어간다.(과적합)
  - 그렇기 때문에 어느 순간부터는 validation loss가 커지게 된다.

  - early stopping은 patience라는 값이 있는데 이는 기본적으로 validation loss가 낮아지지 않더라도(모델이 개선되지 않더라도) 얼마나 더 참고 기다리겠는지에 대한 지표이다.
  - 이는 validation loss값은 조금씩 흔들리는 일이 있기 때문에 성급하게 판단하지 않으려 하기 위함이다.
  - 이렇게 해서 early stopping으로 멈춘 경우에는 마지막 epoch의 결과가 최적의 결과는 아니다.
  - 그렇기 때문에 best checkpoint를 저장해야 한다.
  - 또한 patience에 더불어 한 가지 값이 더 있는데, min_delta로 validation loss가 min_delta보다 더 작아져야 개선된 것으로 생각하겠다는 것이다.
  - 만약 best validation loss가 0.01이었고, min_delta가 0.002라고할 때 새로운 validation loss가 0.009라면 개선된 정도가 0.001로 min_delta인 0.002보다 작기 때문에 개선되지 않은 것을 ㅗ간주한다.

  - 이미지를 한 줄로 펼치지 않고 작은 영역을 필터를 통과시켜 지역 패턴을 찾는다.
  - CNN의 핵심 아이디어는 다음과 같다.
    - 국소 연결: 한 번에 전체 이미지를 보지 않고 작은 영역을 살펴본다.
    - 가중치 공유: 같은 필터를 여러 위치에서 반복 적용하여 비슷한 패턴을 같은 방식으로 찾는다.
  - 하나의 필터가 만든 결과를 feature map이라고 한다.
  - 필터를 거친 feature map을 반복해서 필터를 통과시킬 수 있는데, 얕은 곳은 단순한 특징을 표현하고, 깊어지면 이들을 조합한 복잡한 패턴을 표현하게 된다.
  - CNN은 기본적으로 특징을 추출하는 과정과 이렇게 추출된 특징을 분류하는 과정으로 나뉜다.
  - `nn.Conv2d`의 인자들은 다음과 같다.
    - `in_channels`: 입력 이미지 또는 feature map의 채널 수
    - `out_channels`: 만들어낼 feature map 수
    - `kernel_size`: 필터의 크기
    - `padding`: 가장자리에 추가할 패딩의 두께
    - `stride`: 필터가 이동하는 간격
- 딥러닝 기초11-3
  - padding이 필요한 이유는 가장자리는 자주 곱해지지 않기 때문에 가장자리의 특징이 무시될 수 있어. 가장자리의 특징을 더 반영하기 위함이다.
  - 또한 padding 없이는 Conv layer를 여러 번 쌓으면 feature map의 크기가 점점 줄어들지만 padding을 설정하면 feature map의 크기가 유지될 수 있다.
  - 출력 크기 공식은 `H_out = floor((H_in + 2 * padding - dilation * (kernel_size - 1) - 1) / stride + 1)`이다.
    - `H_in`: 입력 height
    - `P`: padding
    - `K`: kernel size
    - `S`: stride
  - 중요해서 외울건 아니고 이거에 따르면 padding으로 인해서 어느정도 feature map의 크기를 유지할 수 있는 것이다.

## 왜 중요한가
- 학습 모드와 평가 모드에서의 동작이 서로 다른 모듈이기 때문에 중요하다.
- 이전까지는 학습 모드와 평가 모드에서의 동작이 서로 다른 모듈이 없었지만 여기서부터는 확실하게 구분하지 않으면 평가모드에서 모델의 변화가 발생할 수 있기 때문에 중요하다.
- 또한 모델의 과적합을 방지하기 위한 규제에 속하기 때문에 과적합 때문에 문제를 겪고 있을 때 사용하기 위해서 중요한 요소들이다.
- 이미지를 처리하기 위한 대표적인 방법이 CNN이기 때문에 간단한 로직이더라도 중요하다.

```python
# dropout 동작 확인 예제
import torch
import torch.nn as nn

# 결과를 어느 정도 재현하기 위해 seed를 고정합니다.
# Dropout은 무작위로 값을 끄기 때문에 seed 없이 실행하면 결과가 달라질 수 있습니다.

# Dropout은 학습 모드에서 무작위로 일부 값을 0으로 만듭니다.
dropout.train()
y_train = dropout(x)

# 평가 모드에서는 Dropout이 비활성화되어 입력이 그대로 통과합니다.
dropout.eval()
y_eval = dropout(x)

print("input       :", x)
print("train output:", y_train)
print("eval output :", y_eval)
```

```python
# batchnorm을 사용하는 mlp모델 예제
import torch
import torch.nn as nn

class BatchNormMLP(nn.Module):
    """
    BatchNorm1d를 적용한 MLP 모델입니다.
    """

    def __init__(self, input_dim=784, hidden_dim=128, num_classes=10):
        super().__init__()

        # 이미지를 2차원 Tensor로 펼칩니다.
        self.flatten = nn.Flatten()

        # 첫 번째 선형층입니다.
        # 출력 feature 수가 hidden_dim이므로 BatchNorm1d도 hidden_dim을 받습니다.
        self.fc1 = nn.Linear(input_dim, hidden_dim)

        # BatchNorm1d는 feature 차원 수를 인자로 받습니다.
        # fc1의 출력이 (batch_size, hidden_dim)이므로 hidden_dim을 넣습니다.
        self.bn1 = nn.BatchNorm1d(hidden_dim)

        # BatchNorm 뒤에 ReLU를 적용하는 구조를 자주 사용합니다.
        self.relu = nn.ReLU()

        # 출력층입니다.
        self.fc2 = nn.Linear(hidden_dim, num_classes)

    def forward(self, x):
        # x shape: (batch_size, 1, 28, 28)
        x = self.flatten(x)

        # x shape: (batch_size, 784)
        x = self.fc1(x)

        # x shape: (batch_size, hidden_dim)
        # BatchNorm은 이 hidden feature 분포를 안정화합니다.
        x = self.bn1(x)

        # 정규화된 값을 ReLU에 통과시킵니다.
        x = self.relu(x)

        # logits shape: (batch_size, num_classes)
        logits = self.fc2(x)

        return logits
```

```python
# early stopping 클래스 예제
import math


class EarlyStopping:
    """validation loss 기준 Early Stopping 상태를 관리합니다."""

    def __init__(self, patience=3, min_delta=0.0):
        if (
            isinstance(patience, bool)
            or not isinstance(patience, int)
            or patience < 1
        ):
            raise ValueError("patience는 1 이상의 정수여야 합니다.")

        min_delta = float(min_delta)
        if not math.isfinite(min_delta) or min_delta < 0:
            raise ValueError("min_delta는 0 이상의 유한한 값이어야 합니다.")

        self.patience = patience
        self.min_delta = min_delta
        self.best_loss = None
        self.counter = 0
        self.should_stop = False

    def step(self, valid_loss):
        """
        반환값:
            (should_stop, improved)
        """

        valid_loss = float(valid_loss)
        if not math.isfinite(valid_loss):
            raise ValueError(
                "valid_loss가 NaN 또는 inf입니다. 학습과 데이터를 점검하세요."
            )

        # 이미 중단 조건에 도달한 상태를 다시 진행하지 않습니다.
        if self.should_stop:
            return True, False

        # 첫 유한 loss는 항상 best이므로 checkpoint를 저장합니다.
        if self.best_loss is None:
            self.best_loss = valid_loss
            self.counter = 0
            return False, True

        improvement = self.best_loss - valid_loss

        # 실제로 더 낮고, 개선 폭이 min_delta 이상이어야 합니다.
        # 따라서 min_delta=0이어도 같은 loss는 개선이 아닙니다.
        improved = (
            improvement > 0.0
            and improvement >= self.min_delta
        )

        if improved:
            self.best_loss = valid_loss
            self.counter = 0
        else:
            self.counter += 1

        self.should_stop = self.counter >= self.patience
        return self.should_stop, improved

    def state_dict(self):
        """학습 재개용으로 내부 상태를 기본 자료형으로 반환합니다."""

        return {
            "patience": self.patience,
            "min_delta": self.min_delta,
            "best_loss": self.best_loss,
            "counter": self.counter,
            "should_stop": self.should_stop,
        }

    def load_state_dict(self, state):
        """checkpoint에서 EarlyStopping 상태를 복원합니다."""

        required_keys = {
            "patience",
            "min_delta",
            "best_loss",
            "counter",
            "should_stop",
        }
        missing_keys = required_keys - state.keys()
        if missing_keys:
            raise KeyError(
                f"EarlyStopping 상태 key가 없습니다: {sorted(missing_keys)}"
            )

        patience = int(state["patience"])
        min_delta = float(state["min_delta"])
        best_loss = state["best_loss"]
        counter = int(state["counter"])

        if patience < 1:
            raise ValueError("복원한 patience가 1보다 작습니다.")
        if not math.isfinite(min_delta) or min_delta < 0:
            raise ValueError("복원한 min_delta가 올바르지 않습니다.")

        if best_loss is not None:
            best_loss = float(best_loss)
            if not math.isfinite(best_loss):
                raise ValueError("복원한 best_loss가 유한하지 않습니다.")

        if counter < 0:
            raise ValueError("복원한 counter가 음수입니다.")

        self.patience = patience
        self.min_delta = min_delta
        self.best_loss = best_loss
        self.counter = counter
        self.should_stop = bool(state["should_stop"])
```

```python
# CNN 클래스 예제
import torch
import torch.nn as nn

class SimpleCNN(nn.Module):
    """
    CIFAR-10처럼 3x32x32 이미지를 입력으로 받아
    class별 logits를 출력하는 간단한 CNN 모델입니다.
    """
    def __init__(self, num_classes=10):
        super().__init__()

        # feature extractor는 이미지의 공간적 패턴을 feature map으로 바꿉니다.
        self.features = nn.Sequential(
            # 입력: (N, 3, 32, 32)
            nn.Conv2d(3, 16, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),  # (N, 16, 16, 16)

            nn.Conv2d(16, 32, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),  # (N, 32, 8, 8)
        )

        # feature map을 한 줄 feature로 펼칩니다.
        self.flatten = nn.Flatten()

        # classifier는 펼쳐진 feature를 class별 logits로 바꿉니다.
        # 마지막 feature map이 (32, 8, 8)이므로 flatten_dim은 32*8*8입니다.
        self.classifier = nn.Linear(32 * 8 * 8, num_classes)

    def forward(self, x):
        # x shape: (batch_size, 3, 32, 32)
        x = self.features(x)

        # x shape: (batch_size, 32, 8, 8)
        x = self.flatten(x)

        # logits shape: (batch_size, num_classes)
        logits = self.classifier(x)
        return logits
```

## 헷갈렸던 부분 & 해결
- 처음에 Conv에서 채널의 입력 차원과 출력 차원이 다른 것에 대해서 조금 헷갈렸었다.
- 처음에는 출력 차원만큼의 feature map 층이 생기는건가 했었지만 알아보니까 입력 채널 차원이 3이라면 출력 차원은 3개에 대해서 전부 연산한 단일 feature map이 여러 개가 나오는 것이었다.
- 이 과정에서 연산에 사용되는 필터의 값은 전부 달라서 서로 다른 특징을 표현하는데 특화를 하는 것이다.
