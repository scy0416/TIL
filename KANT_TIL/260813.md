## 오늘 배운 것
- 머신러닝 심화3-1
  - 머신러닝에서 편향과 분산을 통해서 모델의 상태를 점검할 수 있다.
  - 편향은 모델이 한쪽으로 쏠리는 것(사격 시 클리크만 조절하면 되는 상태)
  - 분산은 예측이 흔들리는 정도이다.
  - 이 분산과 편향에 따라서 과소적합과 과적합, 학습 상태 등을 판단할 수 있다.
  - 그리고 학습 점수와 검증 점수의 차이가 중요하다.
  - 교차검증(CV)를 통해서 개발 데이터를 여러 묶음(fold)으로 나눠서 검증을 진행한다.
  - 검증에는 AP를 사용한다.
  - 기대 제곱 예측오차는 `Bias^2 + Variance + σ^2`
    - bias는 편향
    - variance는 분산
    - σ^2는 데이터 상에 존재하는 노이즈이다.
  - 기대 제곱 오차는 곡선의 형태이며 가장 낮을 때가 이상적이다.
  - 물론 모든 데이터들이 U자나 최솟값을 보장하지는 않는다고 한다.
  - 학습곡선은 데이터 양을 변경한 여러 반복에 대한 학습 스코어와 검증 스코어 사이의 곡선을 비교하는 것이다.
  - 기본적으로 두 곡선이 가까워지면 좋지만 전체적으로 낮다면 편향이 높은 것이고, 모델의 표현력이 작은 것이다.
  - 학습 스코어는 높은데 검증 스코어와의 차이가 크다면 모델의 표현력은 충분하지만 분산하는 형태이다.
  - 과적합한 경우가 그렇다. 모델의 표현력이 과한 나머지 학습 데이터의 노이즈까지 표현해버리면 발생할 수 있다.
  - 학습 스코어가 높고, 검증 스코어가 가까운 경우가 베스트다.
  - 검증곡선은 폴드를 두고, 조절할 수 있는 하이퍼파라미터를 변경해가면서 그래프를 확인하는 것이다.
  - 이 때 fold의 변동까지 확인한다고 한다.
  - 트리를 예시로 들면 max_depth를 변경해가면서 확인할 수 있다.
  - 트리는 깊이가 깊어질수록 표현력이 오르기 때문에 테스트하기 좋다.
  - 과소적합은 단순히 학습이 부족한 것이므로 학습을 충분히 시킨다.
  - 고편향에 대해서는 특성, 모델의 표현력, 지나친 규체 등을 검토한다.
  - 고분산에 대해서는 그룹 누수, 모델 복잡도, 규제, 데이터 부족을 확인한다.
  - 학습곡선과 검증 곡선을 보고서 결과를 해석하는 것이 좋은 모델을 만드는데 있어 중요한 포인트 같다.
- 머신러닝 심화3-2
  - 규제를 적용하는 대부분의 경우에는 스케일링을 진행하는 것이 좋다.
  - 단위로 인해서 작은 값을 가지는 특성은 비교적으로 큰 값을 가지는 특성과 비슷한 영향력을 가지기 위해서 계수가 커지게 된다.
  - 규제는 큰 계수에 대해서 더 큰 벌점을 부여하기 때문에 스케일링이 필요한 것이다.
  - 각 규제는 `예측 오차 + alpha * 계수 벌점`으로 특성에게 벌점을 부여하고, 높은 벌점을 받은 계수를 각각의 방식으로 처리한다.
  - 규제의 종류에는 L1(Lasso), L2(Ridge), ElasticNet이 있다.
    - 라쏘는 일부 계수를 0으로 만든다.
    - 릿지는 일부 계수를 부드럽게 줄인다.
    - ElasticNet은 라쏘와 릿지를 한 번에 처리한다.
  - 모델에 규제를 가하면 학습 데이터에 대한 과적합이 줄기 때문에 학습 오차는 늘지만 검증 오차는 줄어들게 된다.
  - 하지만 규제가 너무 강하면 학습 오차가 과해지고, 검증 오차또한 과하게 높아질 수 있다.
  - 그래서 alpha는 cv의 오류가 낮은 구간을 선택해야 한다.
  - 릿지는 벌점이 높은 계수에 대해서 축소를 진행해서 전체적인 영향을 맞춘다.
  - 라쏘는 특정 특성을 아예 제외시켜버리는데, 이를 통해서 변수 선택을 하기도 하며, 계산 비용을 낮출 때 사용할 수도 있다.
  - ElasticNet은 alpha를 통해서 전체 벌점을 먼저 계산한 다음 그 벌점에서 L1_ratio를 확인해서 처리하게 된다.
    - l1_ratio가 높으면 L1 규제(라쏘)를 처리하고
    - l1_ratio가 낮으면 L2 규제(릿지)를 처리한다.

## 왜 중요한가
- 이걸 알고있어야 진정으로 좋은 모델을 만들 수 있는 것 같다.
- 현재 상황에 대해서 해석하고, 분석해서 개선하는데에 중요하다.

## 느낌점
- AP가 생각 이상으로 많은 곳에서 사용된다.
- 생각 이상으로 트리가 범용성이 좋은거 같다.
- 직관적이기도 하며, 표현력의 차이가 확실하다.
- 오늘 갑자기 성능 지표를 사용하는 기준에 대해서 생각이 들었는데, 아직은 감이 잡히지를 않는다.

## 코드/예시
```python
depths = np.array([1, 2, 3, 4, 5, 7, 10, 15])
# 반환 배열은 깊이 8개×fold 5개의 train·validation F1입니다.
train_curve, valid_curve = validation_curve(
    tree_pipe(),
    X_dev,
    y_dev,
    param_name="model__max_depth",
    param_range=depths,
    cv=cv,
    scoring="f1",
    n_jobs=1,
)
depth_table = pd.DataFrame(
    {
        "max_depth": depths,
        "train_mean": train_curve.mean(axis=1),
        "train_std": train_curve.std(axis=1, ddof=1),
        "valid_mean": valid_curve.mean(axis=1),
        "valid_std": valid_curve.std(axis=1, ddof=1),
    }
)

# 먼저 validation 평균이 가장 높은 행을 one-SE 기준의 기준점으로 삼습니다.
best_index = int(depth_table["valid_mean"].to_numpy().argmax())
best_mean = float(depth_table.iloc[best_index]["valid_mean"])
best_fold_std = float(depth_table.iloc[best_index]["valid_std"])
# fold 표준편차와 평균의 표준오차를 혼동하지 않도록 별도 변수로 계산합니다.
best_se = best_fold_std / np.sqrt(cv.get_n_splits())
cutoff = best_mean - best_se
# cutoff 이상이면 평균 차이가 1 SE 이내이므로 더 단순한 후보도 허용합니다.
eligible_depths = depth_table.loc[
    depth_table["valid_mean"] >= cutoff, "max_depth"
]
# 허용 집합에서 최소 깊이를 택해 비슷한 성능이라면 더 단순한 트리를 선호합니다.
chosen_depth = int(eligible_depths.min())

# 선택 깊이가 후보 목록에 있고 실제 validation 평균도 cutoff를 넘는지 확인합니다.
assert chosen_depth in depths
assert depth_table.loc[
    depth_table["max_depth"] == chosen_depth, "valid_mean"
].iloc[0] >= cutoff
print(depth_table.round(4))
# 표에서는 평균만 보지 말고 깊이가 커질 때 train-valid gap과 valid_std도 함께 읽습니다.
print(
    {
        "best_depth": int(depth_table.iloc[best_index]["max_depth"]),
        "best_mean": round(best_mean, 4),
        "best_fold_std": round(best_fold_std, 4),
        "best_se": round(best_se, 4),
        "cutoff": round(cutoff, 4),
        "eligible": eligible_depths.astype(int).tolist(),
        "chosen_depth": chosen_depth,
    }
)

plt.plot(depths, depth_table["train_mean"], marker="o", label="train F1")
# 수평선과 수직선은 허용 성능 범위와 실제 선택 깊이를 함께 읽기 위한 기준입니다.
plt.plot(depths, depth_table["valid_mean"], marker="o", label="validation F1")
plt.axhline(cutoff, linestyle="--", color="gray", label="one-SE cutoff")
plt.axvline(chosen_depth, linestyle=":", color="black", label="chosen depth")
plt.xlabel("max_depth")
plt.ylabel("F1")
plt.legend()
plt.show()# 실제로 써본 코드나 예시
```

## 헷갈렸던 부분 & 해결
- 머신러닝 심화2의 실습에서 CV랑 폴드의 개념이 나왔는데 설명이 없어서 뭔지 잘 알지 못했는데 이번에 설명이 나와서 이해할 수 있었다.
- 규제에서 벌점에 대해서 잘못 생각했던 부분이 있었다.
- 라쏘는 결국 계수를 0으로 만들어버리는데, 벌점을 부여하는 의미가 있는건가? 했는데, 확인해보니 벌점이 계수를 직접적으로 바꾸는게 아니라 벌점이 높은 특성을 각각의 규제방법마다 다르게 처리하는거고, 라쏘는 그 중에서 벌점이 높은 특성을 아예 제외시켜버리는 방식이었다.
- 실습을 진행하면서 one-se가 나와서 당황했는데, 클로드와의 대화를 통해서 확실히 알 수 있었다.
- one-se는 모델의 하이퍼파라미터를 조절할 때 사용하는 지표로 F1을 이용한다.
- validation_curve를 사용하면 param_name, param_range를 조절하는데, 이걸 통해서 지정한 하이퍼파라미터를 조절하는 것이 가능하고, 의사결정 트리에서 사용한다면 깊이를 설정할 수 있는 것이다.
- 그리고 cv를 전달해서 각각의 Fold에 대한 F1값이 나온다면 각각의 Fold에 대한 평균을 구하고, 이들의 표준편차를 구하면 SD이다.
- SD를 Fold의 개수의 제곱근으로 나누면 그것이 SE이고, 이 하나의 SE값이 one-SE가 된다.
- 이걸 어디에 쓰냐하면 Fold의 평균 F1들 중에서 가장 큰 값에서 one-SE를 빼면 기준선이 되고, 이 기준선보다 큰 값들 중에서 가장 간단한 값을 고르면 되는 것이다.
- 이렇게 하는 이유는 서로의 성능이 비슷할거라면 복잡한 모델보다 단순한 모델을 고르는 것이 좋게 때문이라고 한다.
