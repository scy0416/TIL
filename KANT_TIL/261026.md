- citation을 위해서 인용되었거나 발췌되었는지를 확인해서 증빙 문장을 연결해줘야 한다.
- `bind_claim`은 출처의 존재, 인용문 포함, URL 형식을 확인해서 정말 인용되었는지를 확인하는 함수이다.
  - 이 함수는 실제로 구동되는 로직에서 사용되지는 않았으며, 실제로 사용된다면 모델이 "어떤 소스로부터 어떤 인용문을 어떻게 주장하는데 사용했다"를 직접 표시해서 검증하는데 사용된다.
  - 이를 통해서 실제로 어떤 문서들이 어디에서 사용되었는지에 대해서 확인하는 것이 가능한다.
- 검색된 문서에 충분한 정보가 포함되지 않는다면 문의 사항에 대해서 유추하거나 보편적인 지식을 통해서 답변해서는 안된다.
- BM25는 기본적으로 TF-IDF랑 비슷한 방식이다.
  - 단어의 빈도에 따라서 값이 증가되는 점(TF)은 같으나, BM25에서는 증가폭이 줄어들다가 포화한다.
  - 단어의 희소성에 따라서 가중치를 주는 IDF는 식이 조금 다르다.
  - 그리고 가장 큰 차이로 BM25는 평균 길이 대비로 조절을 하게된다.
- Dense 검색은 결과벡터가 희소하지 않고 값들고 꽉차있어서 dense검색이고, sparse는 반대로 대부분의 값들이 0인 희소행렬이기 때문에 sparse검색이다.
- BM25도 단어들이 아예 겹치지 않는 경우에는 문서를 제외하기 때문에 상위 결과가 빈 문서가 될 수 있다.
- 단일 검색기가 아닌 여러 개의 검색기를 사용하는 방식의 하이브리드 검색을 할 때에는 점수를 서로 그냥 더해서는 안된다.
- 검색기마다 점수 산정 방식이 다르기 때문에 일반적으로 더해버리면 비중이 큰 값에 다른 순위 정보들이 가려질 수 있다.
- 그렇기 때문에 RRF를 통해서 공정하게 반영되도록 한다.
  - $$RRF\_Score(d \in D) = \sum_{m \in M} \frac{1}{k + r_m(d)}$$
- Bi-Encoder는 질문과 청크를 전부 벡터화를 해서 코사인 유사도를 검사할 수 있는 방식이다.
- Cross-Encoder는 질문과 청크를 한 번에 전달하여 입력된 쌍에 대해서 관련도 점수를 계산해내는 방식이다.
- 리랭킹은 한 번 검색한 문서들을 좀 더 세밀한 모델로 다시 관련도를 확인해서 재정렬하는 과정이다.
- 입력된 쿼리를 완전히 바꾸면 Query Rewrite, 원래 쿼리에 같은 뜻을 가지는 여러 쿼리를 추가로 만든다면 Multi-Query, 원본 질문을 다른 뜻을 가지는 여러 쿼리로 쪼개면 질문 분해이다.
- 문장을 바꿀 때에는 불필요한 유추를 넣지 않고, 의도를 살리면서 표현만 바꾸도록 한다.
- 각각의 문장에 대해서 따로 문서 검색을 해낸 다음에는 하나로 합친다.

## 왜 중요한가
- 문서를 검색해서 출력하는 과정을 대략적으로 봤으며, 어떻게 좋게 검색을 해낼 수 있는가, 더 좋은 결과를 위해서는 한 번 검색한걸 재처리할 필요가 있다는 걸 알 수 있었고, 실제로 코드로 보면서 사용법을 익힐 수 있었다.

## 느낀점
- 마지막의 멀티 쿼리에서 아쉬웠던게, 각각의 문장에 대해서 검색을 따로 한 후에 합치기는 하는데, 그 다음에 어떻게 순서를 정하느냐에 대해서가 없었다.
- 물론 이에 대해서 질문을 했을 때에 리랭킹을 하면 된다고 하셨지만 이거도 문제가 있던게 그럼 어떤 쿼리를 기준으로 리랭킹을 해야하는가였다.
- 이에 대해서 생각했던게 각 쿼리에 대해서 검색을 한 후에 RRF를 하면 어느정도 유효하지 않을까 하는 것이다.
- 물론 이 경우에는 순위가 명확하게 정해지는 검색기를 사용해야한다는 제약이 생기긴 한다.

# pack_context 함수
# 검색 순서대로 근거를 넣되 전체 길이가 max_chars 안에 들어가는 조각만 선택해요.
# 이 함수의 예산은 토큰 수가 아닌 문자 수이고, sources에는 실제 포함한 근거만 기록해요.
def pack_context(rows, max_chars):
    pieces, sources = [], []
    used = 0
    for row in rows:
        label = f"S{len(sources) + 1}"
        piece = f'[{label}] {row["metadata"]["title"]}\n{row["text"]}'
        # 구분용 줄바꿈 두 문자까지 예약해 보수적으로 길이를 계산해요.
        # 큰 조각이 들어가지 않으면 건너뛰고 다음 조각을 확인해요.
        if used + len(piece) + 2 > max_chars:
            continue
        pieces.append(piece)
        # S1 같은 라벨을 청크 ID, 원문 ID, URL과 연결해 답변에서 출처를 복원할 수 있게 해요.
        sources.append({
            "id": label, "chunk_id": row["chunk_id"],
            "document_id": row["document_id"],
            "source_url": row["metadata"]["source_url"],
        })
        used += len(piece) + 2
    return "\n\n".join(pieces), sources

"""6장 2강: 검색→Context→응답. --generate를 줄 때만 실제 Ollama 호출."""
import argparse
import json
from langchain_core.runnables import RunnableLambda
from saved_index import open_saved_index
from rag_steps import prepare, make_messages, response_schema, invoke_model, finish

# --generate를 주지 않으면 실제 검색과 예시 응답 검사까지만 실행해요.

# bline_claim 함수
# 출처 존재 여부, 인용문 포함 여부, URL 형식을 차례로 확인해 실패 원인을 구분해요.
# URL 형식 검사는 실제 페이지 접속이나 공개 열람을 확인하는 검사는 아니에요.
def bind_claim(claim, lookup):
    source = lookup.get(claim["source_id"])
    if source is None:
        return "unknown_source", None
    if claim["quote"] not in source["text"] or not claim["quote"].strip():
        return "quote_not_found", None
    url = source["metadata"]["source_url"]
    if urlparse(url).scheme not in {"http", "https"} or not urlparse(url).netloc:
        return "invalid_url", None
    # 주장과 인용문이 다르면 뜻이 같은지 추가 검토가 필요해요.
    # 원문에 인용문이 있다는 사실만으로 답변의 단위나 조건까지 올바르다고 볼 수 없어요.
    status = "extractive_match" if claim["text"] == claim["quote"] else "review_meaning"
    return status, {"text": claim["text"], "url": url, "quote": claim["quote"]}

# RRF 예제
"""7-2: 7-1에서 실제 검색한 두 순위 목록을 RRF로 결합."""
import json
from collections import defaultdict
from pathlib import Path
from rag_core import reciprocal_rank_fusion

# 이 강의 prepare.py로 만든 두 검색 순위 목록을 읽어요.
# 같은 q06의 결과를 써야 RRF가 서로 다른 질문의 후보를 섞지 않아요.
runs = json.loads(Path("search_runs_07.json").read_text(encoding="utf-8"))
run = next(r for r in runs if r["question_id"] == "q06")
rankings = [run["bm25"], run["dense"]]
print("STEP1")
for name, rows in zip(["BM25", "Dense"], rankings):
    print(name, [(r["document_id"], r["start"]) for r in rows])

# scores는 청크별 합산값, contributions는 검색기마다 더한 값, lookup은 원래 청크 정보예요.
# 최종 점수뿐 아니라 어떤 순위에서 점수를 얻었는지 설명할 수 있도록 나눠 저장해요.
scores = defaultdict(float)
contributions = defaultdict(list)
lookup = {}
# 순위는 1부터 시작하고 각 검색기에서 1 / (60 + 순위)를 더해요.
# 두 검색기에서 모두 나온 청크는 두 값을 받으며 원래 BM25/코사인 점수를 직접 더하지 않아요.
for name, rows in zip(["BM25", "Dense"], rankings):
    for rank, row in enumerate(rows, 1):
        cid = row["chunk_id"]
        lookup[cid] = row
        value = 1 / (60 + rank)
        scores[cid] += value
        contributions[cid].append((name, rank, round(value, 6)))
# 합산값이 높은 순으로 정렬하고 동점은 청크 ID로 고정해요.
# contributions를 읽으면 특정 후보가 순위에서 올라온 이유를 확인할 수 있어요.
order = sorted(scores, key=lambda cid: (-scores[cid], cid))
print("STEP2")
for cid in order[:5]:
    row = lookup[cid]
    print(row["document_id"], row["start"], contributions[cid], round(scores[cid], 6))
print("STEP3", "합집합", len(order))
# 각 검색기의 후보 수를 바꾸되 최종 반환 개수는 3으로 고정해요.
# 후보를 일찍 잘라 버리면 RRF가 필요한 청크를 되살릴 수 없어요.
for candidate_k in [2, 4, 6]:
    result = reciprocal_rank_fusion([rows[:candidate_k] for rows in rankings], k=3)
    print("각 검색기 후보", candidate_k, "최종", [(r["document_id"], r["start"]) for r in result])

# 리랭킹 예제
"""7-3: 실제 다국어 CrossEncoder의 질문-청크 쌍 점수."""
import argparse
import json
import os
from pathlib import Path
from rag_core import reciprocal_rank_fusion

# --skip-model은 후보 구성만 확인하고 실제 재정렬 모델 실행을 생략해요.
# 기본 실행은 모델을 내려받아 CPU에서 질문-청크 쌍을 함께 평가해요.
parser = argparse.ArgumentParser()
parser.add_argument("--skip-model", action="store_true")
parser.add_argument("--model", default="cross-encoder/mmarco-mMiniLMv2-L12-H384-v1")
args = parser.parse_args()
# RRF로 넓게 모은 후보에 동일 질문을 각각 짝지어요.
# CrossEncoder는 이 쌍을 함께 읽으므로 문서 벡터를 미리 계산하는 Dense 검색과 계산 구조가 달라요.
runs = json.loads(Path("search_runs_07.json").read_text(encoding="utf-8"))
run = next(r for r in runs if r["question_id"] == "q06")
candidates = reciprocal_rank_fusion([run["bm25"], run["dense"]], k=8)
pairs = [(run["question"], c["text"]) for c in candidates]
print("STEP1", "후보", len(candidates), "점수화할 쌍", len(pairs))
print("첫 후보", candidates[0]["document_id"], candidates[0]["start"])
print("질문:", pairs[0][0])
print("본문:", pairs[0][1])
print("STEP2", [(n, len(pairs[:n])) for n in [2, 4, 8]])
if args.skip_model:
    print("MODEL_NOT_RUN: 후보와 입력 쌍만 확인했습니다.")
else:
    import torch
    from sentence_transformers import CrossEncoder
    # Identity를 사용해 원래 logit을 받아요. 값이 음수이거나 1을 넘어도 확률 오류가 아니에요.
    # max_length=256이므로 질문과 본문을 합친 길이가 이 한도를 넘는지 다음 출력에서 확인하세요.
    model = CrossEncoder(args.model, device="cpu", max_length=256,
                         activation_fn=torch.nn.Identity(),
                         cache_folder=os.environ.get("RAG_MODEL_CACHE"))
    lengths = [len(model.tokenizer(q, text)["input_ids"]) for q, text in pairs]
    print("PAIR_TOKENS", lengths)
    # 네 쌍씩 묶어 추론한 뒤 높은 점수부터 재정렬해요.
    # 기존 후보 위치 i와 새 순위를 함께 남겨 어느 근거가 올라오고 내려갔는지 확인해요.
    values = model.predict(pairs, batch_size=4, show_progress_bar=False)
    order = sorted(range(len(values)), key=lambda i: (-float(values[i]), candidates[i]["chunk_id"]))
    print("STEP3", "model", args.model)
    for rank, i in enumerate(order, 1):
        c = candidates[i]
        print(rank, c["document_id"], c["start"], "이전", i+1, "logit", round(float(values[i]), 4))
    # 새 순위와 옛 순위를 파일로 저장해 재정렬의 효과를 질문별로 대조할 수 있게 해요.
    rows = [{"chunk_id": candidates[i]["chunk_id"], "old_rank": i+1,
             "new_rank": rank, "score": float(values[i])}
            for rank, i in enumerate(order, 1)]
    Path("rerank_07.json").write_text(json.dumps(rows, ensure_ascii=False, indent=2), encoding="utf-8")

# 원질문과 사람이 작성한 검색 표현 두 개를 같은 BM25 검색기에 넣어요.
# 기본 실습의 재작성 문장은 생성 모델 출력이 아니에요.
chunks = json.loads(Path("chunks.json").read_text(encoding="utf-8"))
current = [c for c in chunks if c["metadata"]["status"] == "current"]
golden = [json.loads(s) for s in Path("golden.jsonl").read_text(encoding="utf-8").splitlines()]
question = next(g["question"] for g in golden if g["question_id"] == "q10")
variants = [question, "교육비 지원 수강 완료 후 제출합니다", "직무 교육비 정산 제출합니다"]
print("STEP1", question)
for q in variants:
    rows = bm25(q, current, k=3)
    print(q, [(r["document_id"], r["start"]) for r in rows])
# 서로 다른 질의에서 찾은 결과를 chunk_id로 합쳐 중복을 제거해요.
# 이 합집합은 첫 등장 순서이며 통합 관련도 순위를 다시 계산한 결과는 아니에요.
union = {}
for q in variants:
    for row in bm25(q, current, k=3):
        union.setdefault(row["chunk_id"], row)
print("STEP2", "합집합", len(union), [(r["document_id"], r["start"]) for r in union.values()])
# 교육비 근거 본문을 읽어 실제 필요한 서류가 포함됐는지 확인해요.
# 결과 수가 늘어난 것과 질문에 필요한 근거를 찾은 것은 구분해야 해요.
for row in union.values():
    if row["document_id"] == "education":
        print("교육비 근거:", row["text"])
print("STEP3", "중복 질의 제거", len(list(dict.fromkeys(variants + [variants[0]]))))
