- 딥러닝 기초5-3
  - optimizer는 loss를 직접 보지 않고 backward 때에 파라미터마다 계산해둔 gradient를 읽어서 처리한다.
  - loss function은 현재 예측의 오차 계산, backward는 각 파라미터에 대한 gradient 계산, optimizer는 gradient를 사용해서 파라미터를 변경한다.
  - optimizer가 새로운 가중치를 구하는 방식은 다음과 같다.
  - `new_weight = weight - update * lr`
  - 이는 모든 optimizer들의 공통 골격이고, SGD에서는 이 update값이 단순 gradient이다.
  - 그렇게 새로운 가중치가 만들어지면 한 스텝이 끝난 것이고, 이 이후에도 계속해서 스텝들을 반복해서 개선해나간다.
  - learning rate가 너무 크면 적절한 위치를 지나칠 수 있고, 일어면 발산이나 진동을 하게 되며, 이를 overshoot이라고 한다.
  - 그렇다고 너무 작은 값은 최적에 값에 도달하기까지 너무 오랜 시간이 걸리기 때문에 꼭 좋은 것이 아닐 수도 있다.
  - learning rate의 값마다의 결과를 유효하게 비교하기 위해서는 긱 learning rate마다 모델을 새로 만드는 것이 아니라 한 모델을 반복해서 사용해야 한다.
  - 만약 새로운 모델을 만들어서 사용하면 파라미터들이 서로 다르게 되고, learning rate가 아니라 파라미터가 원인이 될 수도 있다.
  - SGD는 그라디언트를 찾아내는 방식이 기본적으로 미니 배치방식이다.
  - 미니 배치방식은 기본적으로 속도가 빠르지만 노이즈가 끼게 된다.
  - SGD에 모멘텀을 넣은 방식도 있는데, 이전까지의 이동 방향으로의 관성이 추가되어 뒤로 돌아가려 해도 관성에 의해서 가던 방향쪽으로 힘이 많이 가해진다.
  - Adam은 전체 파라미터에 대해서 정해진 lr을 적용한 것과 다르게 파라미터마다 lr을 다르게 적용할 수 있는 optimizer이다.
  - Adam이 저장하는 정보는 두 가지이다.
    - 1차 모멘트 m: 최근 gradient 방향의 평균
    - 2차 모멘트 v: 최근 gradient 크기 제곱의 평균
  - m은 나아갈 방향을 정하고, v는 얼마나 나아갈지에 대해서 정한다.
  - v는 gradient의 값이 클수록 커지는데, 이는 v의 값이 클수록 가파른 곳이라는 것이고, 한 번에 멀리 가면 overshoot할 확률이 크다는 것이다.
  - 그렇기 때문에 gradient가 꾸준히 컸다면 보폭이 작고, gradient가 낮았다면 멀리 가도 overshoot할 확률이 작기에 더 멀리 나아간다.
  - Adam은 이력들을 쌓아가면서 사용하는 것이기 때문에 매 step마다 새로 만들어서는 안된다.
  - 대부분의 경우에서 Adam이 SGD보다 좋다고 하지만 언제나 그런것은 아니기 때문에 잘 고려해야 판단해야 한다.

## 코드/예시
```python
# 직접 구한 loss와 MSELoss를 통해서 구현 결과가 같음을 확인하는 예제
import torch
import torch.nn as nn

pred = torch.tensor([[2.5], [3.0], [4.0]])
target = torch.tensor([[3.0], [2.0], [5.0]])

# 1. 예측값과 정답값의 차이를 계산합니다.
error = pred - target

# 2. 차이를 제곱합니다.
squared_error = error ** 2

# 3. 제곱 오차의 평균을 계산합니다.
manual_mse = squared_error.mean()

# PyTorch MSELoss와 비교합니다.
criterion = nn.MSELoss()
torch_mse = criterion(pred, target)

print("error:")
print(error)
print("squared_error:")
print(squared_error)
print("manual_mse:", manual_mse)
print("torch_mse :", torch_mse)
print("same?", torch.allclose(manual_mse, torch_mse))
```

```python
# learning rate 별 개선정도 비교 예제
import torch
import torch.nn as nn
import torch.optim as optim

# 재현을 위해 seed를 고정합니다.
torch.manual_seed(0)

# y = 2x + 1에 가까운 데이터를 만듭니다.
x = torch.linspace(-1, 1, 100).unsqueeze(1)
y = 2 * x + 1 + 0.1 * torch.randn_like(x)

# 모든 learning rate가 같은 출발점에서 시작하도록
# 하나의 초기 parameter를 복사해 둡니다.
base_model = nn.Linear(1, 1)
initial_state = {
    name: value.detach().clone()
    for name, value in base_model.state_dict().items()
}

def train_with_lr(lr, steps=50):
    """
    주어진 learning rate로 간단한 선형 회귀 모델을 학습하고 loss 기록을 반환합니다.
    """
    model = nn.Linear(1, 1)
    model.load_state_dict(initial_state)

    criterion = nn.MSELoss()
    optimizer = optim.SGD(model.parameters(), lr=lr)

    losses = []

    for step in range(steps):
        # 1. 이전 step의 gradient를 초기화합니다.
        optimizer.zero_grad()

        # 2. 모델 예측을 계산합니다.
        pred = model(x)

        # 3. loss를 계산합니다.
        loss = criterion(pred, y)

        # 4. gradient를 계산합니다.
        loss.backward()

        # 5. parameter를 업데이트합니다.
        optimizer.step()

        losses.append(loss.item())

    return losses

loss_small = train_with_lr(lr=0.001)
loss_good = train_with_lr(lr=0.1)
loss_large = train_with_lr(lr=1.5)

print("small lr first/last:", loss_small[0], loss_small[-1])
print("good lr first/last :", loss_good[0], loss_good[-1])
print("large lr first/last:", loss_large[0], loss_large[-1])
```
```python
# 스텝 별 가중치 변화 확인 예제
import torch
import torch.nn as nn
import torch.optim as optim

# 재현을 위해 seed를 고정합니다.
torch.manual_seed(0)

model = nn.Linear(3, 1)
criterion = nn.MSELoss()
optimizer = optim.SGD(model.parameters(), lr=0.1)

inputs = torch.randn(4, 3)
targets = torch.randn(4, 1)

# 업데이트 전 parameter를 복사해둡니다.
weight_before = model.weight.detach().clone()
bias_before = model.bias.detach().clone()

# 1. gradient 초기화
optimizer.zero_grad()

# 2. forward
outputs = model(inputs)

# 3. loss 계산
loss = criterion(outputs, targets)

# 4. backward
gradient_before_backward = model.weight.grad
loss.backward()

# step 직전에 계산된 gradient를 복사합니다.
weight_grad = model.weight.grad.detach().clone()
bias_grad = model.bias.grad.detach().clone()

# momentum이 없는 SGD의 예상 업데이트를 직접 계산합니다.
expected_weight = weight_before - 0.1 * weight_grad
expected_bias = bias_before - 0.1 * bias_grad

# 5. step
optimizer.step()

weight_after = model.weight.detach().clone()
bias_after = model.bias.detach().clone()

print("gradient before backward:", gradient_before_backward)
print("weight before:", weight_before)
print("weight grad  :", weight_grad)
print("weight expected after:", expected_weight)
print("weight actual after  :", weight_after)
print("bias before:", bias_before)
print("bias grad  :", bias_grad)
print("bias expected after:", expected_bias)
print("bias actual after  :", bias_after)
print("weight formula matches?", torch.allclose(expected_weight, weight_after))
print("bias formula matches?  ", torch.allclose(expected_bias, bias_after))
```

## 헷갈렸던 부분 & 해결
- optimizer들 중에서 SGD만 `new_weight = weight - gradient * lr`인건가 했는데, 그런게 아니라 기본 골격이 `new_weight = weight - update * lr`이었던 것이었다.
- 이 중에서 SGD는 `update`값이 `gradient`인 단순한 방법이고, 나머지 optimizer들은 이 `update`값을 좀 더 복잡한 방식으로 구하는 것이었다.
- Adam에서 m과 v를 구할 때에 왜 gradient가 계속 컸다면 보수적으로 update하고, 계속 작았다면 적극적으로 update하는지 이해하기 못했는데, gradient가 크다는 것은 그 부분의 경사가 가파르단 것이고, 많이 움직이면 overshoot할 가능성이 높다는 것이다.
- 반대로 gradient가 작았다면 그만큼 평단하기 때문에 멀리가도 overshoot하지 않을 것이라 여기고 더 멀리 가는 것이었다.
- 이건 따로 찾아보지 않으면 받아들이기 어려운거 같다.
