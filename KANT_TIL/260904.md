  - 트랜스포머 계열의 모델에는 BERT, GPT, T5등이 있다.
  - Self-Attention은 한 시퀀스 안에서 토큰들이 서로를 참고해 새 표현을 만드는 연산이다.
  - Transformer Block은 Attention, FFN, Residual, LayerNorm을 하나로 묶은 층이다.
  - Transformer Model은 Embedding, 여러 Block, Output Head까지 연결한 전체 모델이다.
  - 인코더의 출력은 입력의 각 위치별 문맥 표현의 집합으로 `memory`라고도 한다.
  - 디코더는 target토큰과 함께 이 `memory`를 크로드 어텐션 연산을 한다.
  - target에 대해서는 과거만 보는 Causal Self-Attention을 한다.
  - 그리고 FFN을 통해서 각 target의 표현을 가공한다.
  - 트랜스포머의 전체 구조는 네 부분으로 볼 수 있다.

| 구간      | 핵심 질문                                 | 대표 요소                    |
|-----------|-------------------------------------------|------------------------------|
| 입력 준비 | 정수 Token ID를 어떤 표현으로 바꿀까요?   | Token Embedding, Position    |
| 문맥화    | 토큰이 다른 토큰을 어떻게 참고할까요?     | Multi-Head Attention         |
| 표현 가공 | 각 토큰의 특징을 어떻게 확장, 변환할까요? | FFN, Residual, LayerNorm     |
| Task 출력 | 문맥 표현을 어떤 문제의 점수로 바꿀까요?  | Classification Head, LM Head |
  - 트랜스포머의 동작 과정은 다음과 같다.
    1. 입력과 출력 토큰을 벡터로 바꾼다.
       - 이 때, 단순히 벡터의 형태로 만들면 토큰끼리의 순서에 대해서 알 수 없기 때문에 위치 인코딩을 진행한다.
    2. 인코더가 입력 전체를 문맥화한다.
       - 한 블록마다 MHA와 FNN으로 구성된다.
    3. 디코더가 미래의 정보는 보지 않으면서 현재까지의 출력을 읽는다.
       - 미래를 가리기 위해서 디코더는 Masked Multi-Head Attention을 사용한다.
       - Masked Multi-Head Attention은 Causal Mask를 적용한다.
    4. 디코더가 인코더의 정보를 Cross-Attention으로 참고한다.
       - 이 때의 연산은 QKV를 동일하게 만들어서 처리하지만 Q는 자기자신의 hidden state의 Q이고, KV는 인코더의 출력인 memory에 대한 KV를 계산해서 사용한다.
       - 그러니까 현재 내가 하고 있는 말에서 입력의 어떤 문맥을 필요로 하는가를 찾는 과정이다.
    5. Linear와 Softmax가 다음 토큰 후보를 만든다.
       - 최종 hidden state를 사용해서 Linear가 logits를 만들고, Softmax를 통해 확률 분포를 만들게 된다.
  - 트랜스포머는 인코더와 디코더의 존재에 따라서 세 가지로 구분된다.
    - Encoder-only
      - 인코더만 존재하는 구조로 분류, 검색, 개체명 인식이 좋다.
      - BERT 계열
      - 입력 전체를 양방향으로 참고해 이해 줌심 표현을 만든다.
    - Decoder-only
      - 이전 토큰만 보며 다음 토큰을 예측하며 대화, 생성, 코드 생성에 좋다.
      - GPT 계열
    - Encoder-Decoder
      - 입력 이해 후 조건부 출력 생성에 좋고, 번역, 요약에 사용된다.
      - T5 계열
      - 인코더가 입력을 이해하고 디코더가 인코더가 이해한 입력을 통해서 출력을 생성한다.
  - 트랜스포머 본체가 문맥 표현을 만들면 Output Head가 종류에 따라 Linear나 LM Hear를 통해서 분류 logits나 언어모델 logits를 만든다.
  - 이 때 본체의 결과는 hidden state, head의 결과는 logits이다.

  - 시퀀스에서 같은 토큰이어도 순서에 따라서 의미가 달라질 수 있다.
  - 그렇기 때문에 같은 토큰이어도 위치에 따라서 다르게 인식되어야 할 필요가 있다.
  - 그러나 기본 토큰 임베딩 정보에는 위치 정보가 포함되어 있지 않기 때문에 따로 위치 정보를 추가시켜주는 과정을 거친다.
  - 이렇게 만들어진 표현이 최종 트랜스포머의 입력이 된다.
  - 위치 임베딩 방식은 두 방식이 있다.
    - Learned Position Embedding
      - 위치에 대한 정보를 학습 가능한 파라미터로 두는 방식으로 학습 가능한 위치 파라미터의 개수는 미리 정해두고 학습을 한다.
      - 그렇기 때문에 사전 설정된 길이를 넘어서면 모델은 그 위치에 대한 정보를 알지 못하기 때문에 시퀀스를 잘라내야 한다.
    - Sinusoidal Positional Encoding
      - sin/cos 규칙 기반으로 절대 위치를 주입하는 방식으로, 토큰끼리의 상대 거리를 모델이 인식할 수 있게 된다.
      - 규칙 기반이기 때문에 모델이 학습할 대상이 아니고, 모델이 이 위치 정보와 함께 학습하기를 기대하는 것이다.
      - 또한 sin/cos를 사용하기 때문에 정해진 개수가 없어 필요에 따라서 얼마든지 시퀀스의 길이를 늘릴 수 있다.
      - 물론 시퀀스를 늘릴 수 있는 것과 모델의 성능은 별개의 요소이다.
- 딥러닝 심화4-3

  - FFN은 각 토큰마다 MLP를 적용해 비선형적으로 변환한다.

  - 인코더는 토큰이 전체 시퀀스에 대해서 문맥을 파악하기 때문에 양방향 문맥화에 강하다.
  - 문장 분류는 hidden state에서 대표 문자 표현 또는 pooling 결과를 Classification Head를 통해서 분류를 한다.
  - 토큰의 태깅같은 토큰 분류를 위해서는 각 토큰마다 Classification Head를 통해서 클래스를 분류한다.

- 딥러닝 심화4-5
  - Position-wise FFN은 모든 시퀀스마다 한 번에 처리되며, 각 토큰마다 같은 FFN을 다로 처리한다.
  - 셀프 어텐션은 토큰 사이의 정보를 맥락에 따라 섞고, FFN은 각 토큰 벡터의 차원을 변환시킨다.
  - 비선형 활성화는 정보를 죽이기 때문에 미리 공간을 늘려놓는 것이다.
  - Residual Connection은 서브 레이어의 출력에 원래 입력을 더하는건데, 이를 통해서 그래디언트의 소실을 방지한다.
  - 지름길이라는 표현으로도 쓰이는데, 미분을 해보면 왜 그런 것인지 알 수 있다.
  - 층이 연결된 구조라면 깊어질수록 경사 소실과 폭발의 위험을 가지게 된다.
  - 그러나 원래 입력을 더하게 된다면 미분 시에 항에 1이 무조건 더해지게 된다.
  - 미분값이 1보다 작은 경우에 소실이 발생할 수 있는거기 때문에 1을 더함으로써 소실의 문제는 사라진다.
  - 이제 폭발의 위험이 있는데, 이를 위해서 Norm을 처리해준다.
  - 이 Norm은 미분을 했을 때의 안정적인 값을 나올 수 있도록 만들어준다.
  - 그러니까 Add&Norm은 경사 소실과 폭발을 방지하는 장치인 것이다.
  - LayerNorm은 각 토큰의 feature 축에 대해서 평균과 분산을 계산해서 처리한다.
  - 모델 자체가 자기 회귀적으로 시퀀스의 길이가 변동적이기 때문에 배치나 시퀀스를 기준으로 처리하는 것은 불안정적이다.
  - norm 단계는 norm을 먼저 하는지 residual을 먼저 하는지에 따라서 post-norm과 pre-norm으로 구분된다고 한다.
  - Attention is All You Need에서는 Post-Norm방식으로 설명을 하며, 서브레이어의 결과에 residual을 한 결과를 norm하고, pre-norm은 norm을 한 결과를 서브레이어에 넣고, residual한다.

```python
# 트랜스포머 전체 과정 shape 관찰 예제
import torch
from torch import nn

# 실행할 때마다 같은 가상 입력과 초기 가중치를 만들기 위해 seed를 고정합니다.
torch.manual_seed(42)

# Shape 기호를 실제 숫자로 정의합니다.
BATCH_SIZE = 2       # B: 한 번에 처리하는 샘플 수
SOURCE_LENGTH = 5    # S: Encoder에 들어가는 Source 토큰 수
TARGET_LENGTH = 4    # T: Decoder에 들어가는 Target 토큰 수
D_MODEL = 16         # D: 각 토큰을 표현하는 hidden dimension
NUM_HEADS = 4        # H: Multi-Head Attention의 head 수
VOCAB_SIZE = 100     # V: 교육용 vocabulary 크기

# PyTorch의 reference Transformer를 만듭니다.
# batch_first=True를 사용하면 입력 shape을 [B, L, D] 순서로 다룰 수 있습니다.
transformer = nn.Transformer(
    d_model=D_MODEL,
    nhead=NUM_HEADS,
    num_encoder_layers=2,
    num_decoder_layers=2,
    dim_feedforward=32,
    dropout=0.0,          # Shape 관찰을 단순하게 하기 위해 Dropout을 끕니다.
    batch_first=True,
)

# 이미 Embedding까지 끝난 Source 표현이라고 가정합니다.
# Shape: [B, S, D]
source_hidden = torch.randn(
    BATCH_SIZE,
    SOURCE_LENGTH,
    D_MODEL,
)

# 이미 Embedding까지 끝난 Target 표현이라고 가정합니다.
# Shape: [B, T, D]
target_hidden = torch.randn(
    BATCH_SIZE,
    TARGET_LENGTH,
    D_MODEL,
)

# Decoder가 미래 Target 위치를 보지 못하도록 Causal Mask를 만듭니다.
# Shape: [T, T]
target_mask = nn.Transformer.generate_square_subsequent_mask(
    TARGET_LENGTH
)

# Transformer 본체를 통과합니다.
# Decoder의 각 Target 위치에 대한 hidden state가 반환됩니다.
# 예상 Shape: [B, T, D]
decoder_hidden = transformer(
    src=source_hidden,
    tgt=target_hidden,
    tgt_mask=target_mask,
)

# Transformer 본체의 hidden state는 아직 vocabulary 점수가 아닙니다.
# LM Head가 마지막 차원 D를 vocabulary 차원 V로 바꿉니다.
lm_head = nn.Linear(
    in_features=D_MODEL,
    out_features=VOCAB_SIZE,
)

# 각 Target 위치에서 vocabulary 전체에 대한 logits를 만듭니다.
# Shape: [B, T, V]
logits = lm_head(decoder_hidden)

print("source_hidden:", source_hidden.shape)
print("target_hidden:", target_hidden.shape)
print("target_mask:", target_mask.shape)
print("decoder_hidden:", decoder_hidden.shape)
print("logits:", logits.shape)

# Shape을 코드로 검증하면 뒤의 실습에서 구조 오류를 빠르게 찾을 수 있습니다.
assert decoder_hidden.shape == (
    BATCH_SIZE,
    TARGET_LENGTH,
    D_MODEL,
)
assert logits.shape == (
    BATCH_SIZE,
    TARGET_LENGTH,
    VOCAB_SIZE,
)
```
```python
# learned position embedding 구현 예제
import torch
from torch import nn

# 실행할 때마다 같은 초기값을 만들기 위해 seed를 고정합니다.
torch.manual_seed(42)

# 교육용 설정값입니다.
BATCH_SIZE = 2
SEQUENCE_LENGTH = 5
VOCAB_SIZE = 100
MAX_POSITION = 32
D_MODEL = 16

# 두 문장의 Token ID를 가정합니다.
# Shape: [B, L]
input_ids = torch.tensor(
    [
        [10, 20, 30, 40, 50],
        [11, 21, 31, 41, 51],
    ],
    dtype=torch.long,
)

# Token ID를 D차원 의미 벡터로 바꾸는 학습 가능한 Embedding입니다.
token_embedding = nn.Embedding(
    num_embeddings=VOCAB_SIZE,
    embedding_dim=D_MODEL,
)

# Position ID를 D차원 위치 벡터로 바꾸는 학습 가능한 Embedding입니다.
position_embedding = nn.Embedding(
    num_embeddings=MAX_POSITION,
    embedding_dim=D_MODEL,
)

# 0, 1, 2, 3, 4의 위치 ID를 만듭니다.
# Shape: [L]
position_ids = torch.arange(
    SEQUENCE_LENGTH,
    dtype=torch.long,
)

# Batch의 각 문장에 같은 위치 ID를 사용하도록 batch 축을 추가합니다.
# unsqueeze(0): [L] -> [1,L]
# expand(B,-1): [1,L] -> [B,L]
position_ids = position_ids.unsqueeze(0).expand(
    BATCH_SIZE,
    -1,
)

# Token ID를 의미 벡터로 변환합니다.
# Shape: [B,L] -> [B,L,D]
token_hidden = token_embedding(input_ids)

# Position ID를 위치 벡터로 변환합니다.
# Shape: [B,L] -> [B,L,D]
position_hidden = position_embedding(position_ids)

# 의미와 위치 정보를 원소별로 더합니다.
# 두 Tensor의 shape이 같아야 합니다.
transformer_input = token_hidden + position_hidden

print("input_ids:", input_ids.shape)
print("position_ids:", position_ids.shape)
print("token_hidden:", token_hidden.shape)
print("position_hidden:", position_hidden.shape)
print("transformer_input:", transformer_input.shape)

assert token_hidden.shape == (
    BATCH_SIZE,
    SEQUENCE_LENGTH,
    D_MODEL,
)
```

```python
# Causal Mask 만들기 예제
import torch


def make_causal_mask(sequence_length: int) -> torch.Tensor:
    """미래 Key 위치를 True로 표시하는 bool Causal Mask를 만듭니다."""

    # 모든 위치 쌍을 False로 시작합니다.
    # Shape: [L,L]
    mask = torch.zeros(
        sequence_length,
        sequence_length,
        dtype=torch.bool,
    )

    # diagonal=1은 주대각선 바로 위부터 선택합니다.
    # 따라서 현재 위치보다 오른쪽에 있는 미래 위치만 True가 됩니다.
    mask = torch.triu(
        torch.ones_like(mask),
        diagonal=1,
    )

    # PyTorch MultiheadAttention의 bool attn_mask에서는
    # True가 Attention에서 차단할 위치를 뜻합니다.
    return mask


causal_mask = make_causal_mask(sequence_length=5)

print(causal_mask)
print("shape:", causal_mask.shape)

assert causal_mask.shape == (5, 5)
```

```python
# Position-wise FFN 구현 예제
from __future__ import annotations

import torch
from torch import Tensor, nn


class PositionWiseFFN(nn.Module):
    """각 토큰 위치에 같은 두 층 MLP를 적용합니다."""

    def __init__(
        self,
        d_model: int,
        d_ff: int,
        dropout: float = 0.0,
    ) -> None:
        super().__init__()

        # 첫 Linear는 마지막 hidden dimension을 D에서 D_ff로 확장합니다.
        self.linear_in = nn.Linear(
            in_features=d_model,
            out_features=d_ff,
        )

        # GELU는 Transformer 계열에서 널리 사용하는 비선형 activation 중 하나입니다.
        self.activation = nn.GELU()

        # 학습 시 일부 activation을 확률적으로 0으로 만드는 regularization입니다.
        self.dropout = nn.Dropout(dropout)

        # Residual 덧셈을 위해 마지막 차원을 다시 D로 줄입니다.
        self.linear_out = nn.Linear(
            in_features=d_ff,
            out_features=d_model,
        )

    def forward(self, x: Tensor) -> Tensor:
        """입력 [B,L,D]를 같은 shape의 새 토큰 표현으로 변환합니다."""

        # [B,L,D] -> [B,L,D_ff]
        hidden = self.linear_in(x)

        # Shape은 유지되고 값에 비선형 변환이 적용됩니다.
        hidden = self.activation(hidden)

        # Dropout은 학습 모드에서만 확률적으로 값을 0으로 만듭니다.
        hidden = self.dropout(hidden)

        # [B,L,D_ff] -> [B,L,D]
        output = self.linear_out(hidden)

        # Residual과 더할 수 있는지 shape을 검증합니다.
        assert output.shape == x.shape

        return output


# 실행 예시
BATCH_SIZE = 2
SEQUENCE_LENGTH = 5
D_MODEL = 16
D_FF = 64

x = torch.randn(
    BATCH_SIZE,
    SEQUENCE_LENGTH,
    D_MODEL,
)

ffn = PositionWiseFFN(
    d_model=D_MODEL,
    d_ff=D_FF,
    dropout=0.0,
)

ffn_output = ffn(x)

print("input:", x.shape)
print("ffn_output:", ffn_output.shape)

assert ffn_output.shape == x.shape
```

## 헷갈렸던 부분 & 해결
- 위치 임베딩을 할 때에 위치 벡터를 합연산을 하면 유사도는 같다고 나오니 결국 의미는 유지되는건가 했다.
- 하지만 그런게 아니었고, 위치 임베딩을 하면 서로 달라지는게 맞고, 서로 멀면 멀수록 같은 토큰이어도 의미가 점점 달라진다.
- 난 지금까지 FFN이 그냥 MLP같은걸 이용하는 피드 포워드 + norm이라고 생각했는데, 알고보니 Position-wide FFN이 풀네임이었다.
- FNN하니까 MoE가 생각나서 찾아보니까 전문가라고 표현하지만 뭔가를 능동적으로 활동하지도 않고 이용만 당하는 이상한 이름이다.
- 전문가라서 알아서 선택하는줄 알았지만 그게 아니란걸 알게되었다.
- post-norm과 pre-norm 중에서 pre-norm이 현재 표준인 이유가 그래디언트를 유지하는데 이점이 있기 때문이라고 생각했지만 둘 다 이점은 같고, 학습 안정성이 더 높아서 쓴다고 한다.
