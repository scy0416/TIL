- 딥러닝 심화5-1
  - 언어모델은 텍스트 안에서 토큰이 등장하는 패턴과 문맥 관계를 학습하는 모델로 언어를 이해하기보다는 통계적, 구조적으로 파라미터에 학습한다고 봐야한다.
  - 언어 모델에서 사전 학습이란 곧바로 정답을 찾도록 하는게 아니라 대규모 비라벨 텍스트를 통해서 일반적인 언어의 패턴을 학습하는 과정을 의미한다.
  - 그 뒤에 특정 목적에 맞는 태스크 헤드를 부착해서 사용한다.
  - 사전 학습 때에는 LM Object를 수행하고, 이 때 무엇을 가리고 무엇을 예측하도록 할 것이냐에 따라서 모델의 구조와 백본의 특성이 결정된다.
  - 이렇게 사전 학습된 모델에 실제 문제를 위한 태스크를 적용한다.
    - Fine-tuning: 목적별 데이터로 모델 파라미터를 추가 학습한다.
    - Task Head추가: 분류기처럼 문제에 맞는 출력 계층을 붙인다.
    - Feature 활용: 사전학습 모델의 표현을 다른 모델의 입력으로 사용한다.
    - Prompt 기반 사용: 생성 모델에 지시문과 예시를 제공해 바로 사용한다.
  - LM Objective에서 결정하는 내용들은 다음과 같다.
    - 입력을 어떻게 가공할 것인가?
    - 어떤 위치를 예측하게 할 것인가?
    - 정답은 무엇인가?
    - 어떤 문맥을 볼 수 있게 할 것인가?
    - 어느 출력에 loss를 계산할 것인가?
  - Objective가 가려진 토큰을 맞추는 방식이라면 입력의 중간을 mask로 가리고, 이를 예측하도록 하며, 문맥 표현을 이해하는데 특화될 수 있다.
  - Objective가 이전 토큰의 다음 토큰을 맞추는 방식이라면 현재 토큰들의 이전 토큰들만 보고 다음 토큰만 예측하도록 하며, 이어쓰기와 생성에 특화될 수 있다.
  - 문장을 일부 가리고 원래 토큰을 맞추는 방식은 Masked LM이고, BERT가 대표적인 Masked LM의 백본이다.
    - 가려진 위치를 앞뒤 문맥을 전부 보고서 예측하게 된다.
    - 문장 전체의 문맥을 확인하기 때문에 문장 전체 관계를 반영한 표현을 학습하는데 용이하다.
  - 이전 토큰들을 기반으로 다음 토큰을 맞추는 방식은 Causal LM이고, GPT계열이 대표적인 Causal LM의 백본이다.
    - 각 토큰위치에서 미래 토큰을 볼 수 없다.
    - 토큰 예측 반복을 통해서 새 텍스크를 만들어낼 수 있다.
  - Representation Learning은 입력 데이터의 문맥을 학습하고자 하는 목표이다.
  - MLM은 그 방법 중 하나인 것이다.
  - 전체 문맥을 학습하는 것이 목표이기 때문에, 문장 분류, 토큰 분류, 검색 임베딩, 유사도 계산, 질의응답용 문맥 표현 등으로 연결될 수 있다.
  - Generation Learning은 입력에 대해서 다음에 올 토큰들을 순서대로 예측하고자 하는 목표이다.
  - 목적에 맞게 문장 이어쓰기, 대화, 요약 결과 생성, 코드 생성, 형식화된 응답 생성 등으로 연결될 수 있다.
  - Downstream Task는 사전학습된 모델의 백본을 실제 목적에 적용하는 단계이다.
  - 태스크의 종류에 따라서 입력, 출력, 자연스러운 모델 후보들이 달라지게 된다.
  - 모델을 판단할 때에는 구조와 Objective를 전부 봐야하는데, 구조는 정보가 모델에서 어떻게 흐르는가를, Objective는 어떤 문제에 대해서 학습하는지를 표현하기 때문이다.
- 딥러닝 심화5-2
  - BERT는 **B**idirectional **E**ncoder **R**epresentations from **T**ransformation의 약자이다.
  - 간단하게 트랜스포머 중에서 인코더 블록만을 쌓아 만드는 사전학습 모델이다.
  - BERT의 반환은 대표적으로 [B, L, D]로 각각 배치 크기, 시퀀스 길이, Hidden Dimension이다.
  - Bidirectional에서 양방향은 앞방향, 뒤방향 전부 읽는게 아니라 각 토큰의 앞뒤 방향 전부 참고한다는 것이다.
    - 이를 통해서 각 토큰dl 시퀀스 전체에 걸쳐 모든 토큰들에 접근할 수 있다.
  - BERT의 학습에서 마스크를 통해서 일부를 가리는 이유는 이미 있는 토큰에 대해서 예측을 하는 것은 그저 복사 또는 외우는 것이 될 수 있기 때문이다.
  - Masked LM은 입력 토큰 일부를 변형하고 해당 위치의 원래 토큰을 예측한다.
  - Masked LM의 출력은 hidden state는 [B, L, D]이고, 이 hidden state가 LM Head를 거치면 Logits로 [B, L, V]가 나온다.
  - 여기에서 V는 vocabulary로 어휘사전의 길이와 같다.
  - BERT의 학습 데이터 Masking 방식은 80%는 랜덤하게 [MASK]로 가린다.
  - 10%는 임의의 토큰으로 교체한다.
  - 10%는 원래 토큰을 그대로 유지한다.
  - BERT에는 특수 토큰들이 존재한다.
    - `[CLS]`: 입력 맨 앞에 추가되는 토큰
    - `[SEP]`: 문장의 끝 또는 문장을 구분하는 경계 토큰
    - `[MASK]`: MLM에서 예측할 토큰 위치
    - `[PAD]`: 배치 내의 길이를 맞추기 위한 패딩 토큰
  - BERT에서의 입력 표현은 `Token Embedding + Position Embedding + Token Type Embedding`으로 표현된다.
    - `Token Embedding`은 토큰의 임베딩 벡터이다.
    - `Poistion Embedding`은 토큰의 위치에 대한 벡터이다.
    - `Token Type Embedding`은 문장을 앞 문장인지 뒤 문장인지 구분하게 해주는 벡터이다.
      - 찾아보다 이 벡터는 NSP라는 다음 문장의 연결을 확인하기 위해서 넣은 것이라고 한다.
      - 그렇기 때문에 기본적인 BERT는 문장이 최대 2개까지 들어가는 구조였다고 한다.
  - Masked LM Head는 BERT의 hidden state [B, L, D]를 입력으로 받아서 logits인 [B, L, V]를 출력한다.
- 딥러닝 심화5-3
  - Hugging Face Pipeline이란 허깅페이스에서 제공하는 태스크마다의 추론에 필요한 여러 단계를 하나의 인터페이스로 묶은 고수준 추상화이다.
  - fill-mask Task는 `[MASK]`에 들어갈 후보를 예측하는 태스크이다.
  - 흐름은 다음과 같다.
    - 문자열 입력
    - Tokenizer
    - input_ids, attention_mask
    - Masked LM 모델
    - logits [B, L, V]
    - Mask 위치 선택
    - softmax, top-k
    - token 문자열과 완성 문장 반환
  - 파이프라인을 사용하면 사전 정의된 흐름으로 적은 코드로 원하는 태스크를 진행할 수 있고, 토크나이저와 모델을 함께 불러오게 된다.
  - 결과를 파이썬 딕셔너리의 형태로 확인할 수도 있다.
  - 단, 중간 과정에 대해서 확인하는 것이 힘들고, 커스텀한 처리에 제약이 있다.
  - pipeline사용 시에는 모델의 id만 정해져있다면 모델과 토크나이저를 따로 불러올 필요 없이 알아서 둘 다 불러온다.
  - fill-mask 파이프라인을 통한 결과 후보 하나의 대표 구조는 다음과 같다.
```python
{
    "sequence": "paris is the capital of france.",
    "score": 0.86,
    "token": 3007,
    "token_str": "capital",
}
```
  - `sequence`: Mask Token을 후보로 바꾼 완성 문장
  - `score`: Mask 위치의 vocabulary logits에 softmax를 적용한 뒤 해당 후보가 받은 점수
  - `token`: 후보 토큰의 정수 ID
  - `token_str`: 사람이 읽을 수 있는 토큰 문자열
  - `top_k`를 통해서 상위 n개의 후보만 확인할 수도 있다.
  - `target`에 원하는 토큰 배열을 넣어서 해당하는 타겟들에 대해서만 확인할 수도 있다.
- 딥러닝 심화5-4
  - GPT는 **G**enerative **P**re-trained **T**ransformer의 약자이다.
  - GPT 계열은 디코더만을 여러 층을 쌓아서 이전 토큰을 바탕으로 다음 토큰을 예측하도록 사전학습된 모델이다.
  - 원래 트랜스포머는 인코더가 존재하고, 디코더가 이를 크로스 어텐션하는 과정이 있지만 GPT계열은 Decoder-only모델이라 인코더가 없다.
  - GPT의 종료 조건의 예시는 다음과 같다.
    - EOS Token을 생성
    - `max_new_tokens`에 도달
    - 사용자가 지정한 Stop Sequence와 만남
    - 외부 애플리케이션이 생성을 중단
  - 토큰 선택 규칙은 방식에 따라 Greedy, Sampling, Beam Search방식이 있다.
    - Greedy: 가장 높은 점수의 토큰을 생성한다.
    - Sampling: 확률 분포에서 토큰을 샘플링한다.
    - 여러 후보 경로를 동시에 유지한다.
    - BERT 계열과 마찬가지로 hidden state의 크기는 [B, L, D]이고, LM logits의 크기는 [B, L ,V]이다.

## 왜 중요한가
- 인공지능 모델을 만들고 활용하는 입장이라면 허깅페이스는 당연하게 쓰게 된다.
- 하지만 단순히 그렇다고 해서 알고 쓰는 것은 아니다.
- 그렇기 때문에 기본적으로 어떻게 쓰는지에 대해서 알고 있어야 하며, 또한 모델을 불러와서 어떻게 코드 단에서 활용할 수 있는지 알 수 있어야 한다.

## 느낌점
- 원래부터 허깅페이스에 대해서는 알고 있었고, 몇 번 사용한 적도 있었다.
- 하지만 모델 카드를 제대로 읽을 줄도, 각 파일들이 어떤 의미를 가지고 있는 것인지도 몰랐기 때문에 이제는 읽고 해석해서 사용할 수 있을 것 같다.
- 또한 원래는 모델 서빙 플랫폼에서만 구동해봤고 코드에서는 사용해볼 생각도 못했는데, 이제는 모델을 불러오고 사용하는 방식에 대해서 그 흐름을 알게되었기 때문에 문제 없이 사용할 수 있겠다.
