## 오늘 배운 것
- 학습과 추론에서 쓰이는 데이터타입의 종류는 다양하다.
  - 부동소수점 계열
    - FP64: 과학 계산용으로 학습에는 거의 안쓰인다.
    - TF32: NVIDIA Ampere 이후 텐서코어용 연산 모드로 저장은 FP32 그대로 하고 행렬곱 내부에서만 가수를 10비트로 줄인다.
    - FP8(E4M3): 정밀도 위주로 순전파에서 주로 사용
    - FP8(E5M2): 범위 위주로 연전파에 주로 사용
    - FP6, FP4: 최신 GPU(Blackwell 등)에서 지원하는 초저비트 부동소수점
    - MXFP4, MXFP8: 블록 단위로 공유 스케일을 쓰는 마이크로스케일링 포맷
    - NVFP4: NVIDIA의 4비트 포맷
  - 정수 계열
    - INT8: 가장 보편적인 양자화 포맷
    - INT4: 4비트 정수
    - INT3, INT2: 더 공격적인 양자화 데이터타입
    - 1비트, 1.58비트(삼진): BitNet 계열
  - 코드북/특수포맷
    - NF4: 정규분포 가중치에 맞춘 4비트
    - FP4(bitsandbytes): NF4와 같이 제공되는 4비트 부동소수점 변형
    - GGUF 계열(Q4_K_M, Q5_K_S, Q8_0 등): llama.cpp에서 쓰는 양자화 포맷
    - AQLM, QuIP#, VPTQ: 벡터 양자화(코드북) 계열
- 양자화는 기존의 가중치를 근삿값으로 매핑해서 근삿값들은 codebook으로, 가중치 값은 N개의 비트로 표현된 인덱스값들로 하여 메모리 효율을 올리는 방식이다.
- 메모리에는 인덱스 값들이 올라가게되며, 연산할 때에 복구를 하여 계산을 진행한다.
- 기본적으로 근삿값으로 처리하기 때문에 손실이 발생할 수 있고, 비트 수가 많을수록 손실이 줄어든다.
- 대부분의 가중치 값들이 스케일링을 했을 때에 0에 가까운 정규 분포의 형태를 띄기 때문에 NF4로 중앙(0)을 촘촘하게 하여 손실을 최소화하고자 한다.
- 이 때 만들어지는 scale은 가중치 값 중에서 가장 큰값이며, 양자화할 때에 나누는 값, 복구할 때 곱하는 값으로 쓰인다.
- 이 scale이 전체 모델에서 하나만 존재하는 것이 아니라 그룹마다 따로 존재하는 것이며, 이 때 쌓이는 scale의 크기를 무시할 수 없다.
- 이에 scale도 양자화를 진행하는 2단 양자화를 하며, 이 때에 scale은 8비트 양자화를 한다.
- 그러면 scale의 값이 달라지는 문제가 있을 수 있지만 8비트는 충분히 정확하면서도 메모리도 크게 아낄 수 있어서 보통 8비트를 사용한다고 한다.
- 4비트 양자화면 scale(0.5비트)까지 추가해서 4.5비트가 되며, scale 양자화까지 진행하는 경우에는 4.127비트 양자화가 된다고 한다.
- 이 때 4.5비트나 4.127비트같은 단위가 만들어지는 것은 진짜로 소수점 비트가 존재하는게 아니라 전체 용량 기준으로 압축비를 계산해서 그렇게 되는 것이다.
- 양자화를 할 때에 모든 층들이 압축되는 것은 아니다.
- 영역마다 서로 다르게 압축되거나 확장될 수 있다.
- QLoRA의 핵심은 양자화를 통해서 용량을 줄인다는 것이다.
- LoRA부분은 원래의 입력과 출력 차원을 그대로 사용한다.
- 단, 베이스 모델을 양자화시키기 때문에 기본적으로 학습을 하더라도 성능이 떨어진다.
- QLoRA에서 양자화를 진행한 임베딩 모델의 가중치는 기존이 FP16이었다면 FP32로 만들어서 좀 더 정밀하게 만든다.
- 이는 양자화를 한다는 것 자체가 정밀도를 포기하는 것이기 때문에 FP16으로 진행하면 계산 중에 발산할 수 있기 때문에 문제가 발생할 수 있다.
- 그렇기 때문에 FP32로 만들어주는 것이며, 이 과정에서 크기가 2배가 된다.
- QLoRA의 메모리 이득은 작을 때에는 크게 드러나지 않는다.
- 학습을 하지 않을 때에는 차이가 존재하지만, 작기 때문에 압축되는 정도와 임베딩 모델이 늘어나는 정도가 비슷하다.
- unsloth는 LLM파인튜닝을 적은 메모리로 빠르게 돌리는데 최적화된 오픈소스 라이브러리이다.
- 복잡하고 느린 과정을 간편하고 빠르게 만들어준다.
- `FastLanguageModel.from_pretrained`를 통해서 파인튜닝을 할 수 있고, 여기에서 양자화 수준을 결정할 수 있다.

## 왜 중요한가
- 그렇게 유명한 QLoRA와 양자화이다.
- 안중요할 수 없다.

# 양자화 원리를 간단하게 소개하는 예제
# 2비트 대표값을 쓰는 작은 예제입니다. 실제 NF4 코드북과는 구분합니다.
# 같은 블록의 절댓값 최대치로 정규화하고 가장 가까운 대표값의 번호를 저장합니다.
weights = torch.tensor([-2.0, -0.9, 0.2, 1.3, 2.0])
scale = weights.abs().max()
codebook = torch.tensor([-1.0, -1.0 / 3, 1.0 / 3, 1.0])
indices = (
    (weights[:, None] / scale - codebook[None, :]).abs().argmin(dim=1)
)
restored = scale * codebook[indices]
print("원래 값:", weights.tolist())
print("저장할 2비트 번호:", indices.tolist())
print("복원한 근삿값:", [round(x, 4) for x in restored.tolist()])
print(
    "최대 절대 오차:", round((weights - restored).abs().max().item(), 4)
)
assert (
    indices.min() >= 0 and indices.max() < 4
), '2비트 대표값 번호는 0부터 3까지여야 합니다.'
assert not torch.equal(
    weights, restored
), '계산 결과가 비교 기준 또는 허용 오차와 다릅니다.'

# unsloth의 양자화 모델 로드 예제
from unsloth import FastLanguageModel  # trl, transformers보다 먼저 import

QLORA = True  # True: QLoRA(4비트) / False: LoRA(16비트)
MODEL_ID = "Qwen/Qwen2.5-0.5B-Instruct"
REVISION = "7ae557604adf67be50417f59c2c2f167def9a775"

def load_model():
    return FastLanguageModel.from_pretrained(
        MODEL_ID,
        revision=REVISION,
        max_seq_length=512,
        load_in_4bit=QLORA,
        load_in_16bit=not QLORA,
        use_exact_model_name=True,  # 교안과 같은 모델 저장소 사용
    )

model, tokenizer = load_model()

## 헷갈렸던 부분 & 해결
- 처음 양자화에 대해서 봤을 때, 인덱스를 표현할 때에 값이 n개구나 까지는 이해했는데, 결국 복원해서 메모리에 올리면 압축되지 않는거 아닌가? 하고 생각했다.
- 알고보니 메모리에 적재되는 것은 인덱스에 대한 정보들이고, 그걸 추론하는 과정에 복원해서 처리하는 것이었다.
- 속도가 느려질 수 있지만 메모리 효율이 좋아지는 구조였다.
- 그리고 임베딩 모델의 경우에는 FP16에서 2배를 만들어서 FP32를 만드는데, 굳이 이렇게까지 해서 loss를 감수하는 이유를 알 수가 없었다.
- 교안에는 분명 그쪽을 중심으로 알려주는 느낌이었는데, 따로 찾아보니까 loss보다는 계산 자체를 가능하게 해주는게 목적이었다.
- 양자화라는 것 자체가 원래 정밀도를 포기하는 방식이기 때문에 계산하는 과정에서 오차가 누적될 수 있고, 이 과정에서 발산하게 되면 학습이 정상적으로 진행되지 않는것이다.
- 그래서 정밀도를 좀 더 올릴 수 있는 FP32로 진행하는 것이고, 만약 FP16에서 계산이 터지지 않는다면 FP16을 사용하실 것이라고 하셨다.
