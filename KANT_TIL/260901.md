## 오늘 배운 것
- 딥러닝 심화1-1
  - RNN에서 현재에 대한 시간 맥락인 h_t는 이전 까지의 맥락인 h_{t-1}을 필요로 하기 때문에 시간축 의존성 문제로 계산을 병렬화할 수 없다.
  - transformer 모델에서는 L길이만큼의 토큰이 자기자신을 포함한 L길이만큼의 토큰에 대해서 점수를 확인하기 때문에 점수 메모리가 L^2가 된다.
  - 긴 문맥은 다음과 같은 문제가 겹친다.
    - 장기 의존성
    - 그래디언트 소실/폭발
    - 정보 희석
  - LSTM은 그래디언트의 흐름을 개선할 수는 있었지만 순차성은 유지하기 때문에 병렬 연산이 불가능하다.
  - 트랜스포머는 각 토큰이 모든 토큰에 대한 연관성을 계산하는 행렬 연산이기 때문에 병렬화가 쉽다.
  - 대신 새 토큰의 생성 시에는 순차적 접근이 필요하다.

- 딥러닝 심화2-1
  - 토크나이저를 실행하기 전에 우선적으로 데이터 계약을 고정해야 한다.
  - 토크나이저를 실행하는 중간에는 사람이 문제를 확인하기거 어려워진다.
  - Token: 토크나이저가 모델 입력의 기본 단위로 취금하는 조각
  - Vocabulary: 토큰 문자열과 정수 ID의 고정 대응표
  - Token ID: vocabulary에서 해당 token을 가리키는 정수
  - UNK/OOV: vocabulary로 표현하지 못한 입력 또는 미등록 단위
  - subword는 단어를 재사용되는 조각들로 나눠서 OOV와 토큰의 길이 사이의 균형을 위해서 사용한다.
  - 문자를 그대로 사용하면 길이는 짧지만 OOV(Out Of Vocabulary)문제가 발생하고 문자 단위로 쪼개면 길이가 너무 길며 의미가 함게 쪼개진다.
  - subword를 사용하면 재사용되는 단위로 잘라서 사용할 수 있으며 신조어나 문제가 있는 경우같은 최악의 상황에서도 계속 쪼개서 어떻게든 표현할 수 있다.
  - vocabulary의 크기를 늘리면 그만큼 sequence 길이는 줄어든다.
  - 하지만 LM head 파라미터는 그만큼 늘어나게 된다.
  - Special token은 모델 입력의 구조를 표시한다.
  - LLM 학습에서도 학습된 문장을 기억하는 현상이 발생할 수 있기 때문에 데이터 중복에 의한 누수를 경계해야 한다.
- 딥러닝 심화2-2
  - `AutoTokenizer`는 설명(config)를 통해서 토크나이저를 만들어내는 팩토리이다.
  - API는 여러 개가 있는데, 이 중 5개의 API는 경계를 구분해야한다.

| API                             | 대표 반환         | 주요 용도                       |
|---------------------------------|-------------------|---------------------------------|
| `tokenize(text)`                | token 문자열 list | 분할 결과 관찰                  |
| `convert_tokens_to_ids(tokens)` | ID list           | token<->ID 대응 확인            |
| `encode(text)`                  | ID list           | 한 문장을 간단히 ID로 변환      |
| `tokenizer(texts, ...)`         | `BatchEncoding`   | 실제 model 입력 생성            |
| `decode(ids)`                    | 문자열            | ID를 읽을 수 있는 텍스트로 복원 |
  - `tokenizer(...)`는 batch, padding, truncation, tensor반환을 함께 다루기 때문에 실제 학습과 추론에서 주로 사용한다고 한다.
  - api의 출력 중 `input_ids`와 `attention_mask`는 기본적으로 `[B, L]`이다.
  - 이는 문장수(배치)와 시퀀스 길이이다.
  - 스페셜 토큰은 토크나이저가 넣게 해야한다.
- 딥러닝 심화2-3
  - padding은 짧은 입력을 배치에 넣기 위해서 남는 공간을 padding으로 채우는 것이고, truncation은 모델이나 정책상 최대 길이를 넘는 부분을 자르는 것이다.
  - padding은 불필요한 계산량을 늘릴 수 있고, truncation은 중요한 문맥을 잃을 수 있다.
  - padding 비율이 커지면 불필요한 PAD 계산을 건너뛰는게 유효한 효과가 있다.
  - padding은 정적과 동적이 있고, 정적은 고정된 길이에 맞추는거고, 동적은 batch마다 동적으로 padding량을 조절하는 것이다.
