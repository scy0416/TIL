- LangChain4-1
  - `RunnableLambda`는 파이썬 자체 함수를 `Runnable`로 만들어주는 역할을 한다.
  - `RunnableSequence`는 `Runnable`객체들을 `|`로 연결했을 때 하나의 파이프라인처럼 동작하는 객체이다.
  - `RunnableSequence`는 파이프 방식 외에도 자기자신의 생성자를 통해서도 만드는 것이 가능하다.
  - `RunnableParallel`은 여러 `Runnable`을 병렬로 처리할 수 있게 해주는데, 하나의 입력을 여러 `Runnable`에 입력해서 처리한 후, 결과를 하나의 딕셔너리의 형태로 만들어 넘긴다.
- LangChain4-2
  - `RunnablePassthrough`는 입력된 값을 그대로 유지하는 `Runnable`이다.
  - 이것이 필요한 이유는 입력을 단순히 처리한 이후에 결과만을 넘기면 기존의 입력이 유지가 되지 않기 때문에 필요하다.
  - `RunnablePassthrough.assign()`은 입력 딕셔너리의 기존 필드를 유지하면서 새로운 필드를 추가할 때 사용한다.
- LangChain5-1
- LangChain5-2
  - `with_structured_output()`을 사용하면 모델의 출력을 자동으로 Pydantic 객체로 만들어서 반환해준다.
  - 여기에서 Pydantic 스키마의 규칙을 전부 충족할 것이라고 볼 수 없다고 했지만, `with_structured_output()`에 넣은 스키마가 자체적으로 검증까지 진행한다면 큰 문제는 없다.
  - `PydanticOutputParser`는 Pydantic 스키마 형식으로 출력 형식을 파싱해주는 파서이다.
  - `with_structured_output()`과는 다르게 강제적이지 않으며, 검증도 해준다.
  - `PydanticOutputParser`의 대표적인 오류들은 다음과 같다.
    - JSON 문법 오류
    - 필수 필드 누락
    - `Literal` 허용값 위반
- LangChain5-3
  - Pydantic 검증이 잘못되었다면 다시 한 번 수정요청을 한 뒤에 같은 검증을 진행해야한다.
- LangChain6-1
  - LangChain은 외부 문서를 `Document`라는 형태의 클래스로 관리를 하고, `page_content`와 `metadata`로 구성된다.
  - `page_content`는 문서의 문맥 정보이다.
  - `metadata`는 딕셔너리의 형태로 문서의 정보를 담는다.
  - `metadata`는 문서에 대한 기본정보를 담는 필드로, 키가 정해져있지 않고, 문서의 메터데이터 키를 설계해서 한 애플리케이션에서는 같은 종류의 키를 사용한다.

## 왜 중요한가
- 랭체인에서 가장 중요한 LCEL과 그 활용법이기 때문에 중요하다.
- RAG의 기초라고 할 수 있는 Document에 대해서도 배웠기 때문에 중요하다.

## 느낀점
- 체인에서 디버깅을 하는 과정은 너무 기초적인 부분이어서 솔직히 중요한가 싶었다.
- 또한 실제로는 딕셔너리를 많이 사용할거고, 어떤 키 값이 존재하는지가 중요해질건데, 자료형만으로 문제가 해결될거같지는 않다.
- 솔직히 중요한 부분인데, 너무 빠르게 많이 나가는거 아닌가 싶다.
- 나는 이미 개인적으로 공부한 적이 있기 때문에 큰 문제 없지만 그렇지 않은 사람들이 태반일 것이기 때문에 걱정이다.

## 코드/예시
```python
# RunnableParallel예제
# 일반 함수를 Runnable로 만들 클래스와 병렬 구성을 만들 클래스를 가져옵니다.
from langchain_core.runnables import RunnableLambda, RunnableParallel


# 입력 문자열을 대문자로 바꾸는 첫 번째 branch 함수를 정의합니다.
def make_upper(text: str) -> str:
    # 변환된 문자열을 첫 번째 branch 결과로 반환합니다.
    return text.upper()


# 입력 문자열의 글자 수를 세는 두 번째 branch 함수를 정의합니다.
def count_length(text: str) -> int:
    # 계산한 글자 수를 두 번째 branch 결과로 반환합니다.
    return len(text)


# 같은 문자열을 두 branch에 전달하도록 병렬 구성을 만듭니다.
parallel = RunnableParallel(
    upper=RunnableLambda(make_upper),
    length=RunnableLambda(count_length),
)

# 문자열 한 건을 병렬 Runnable에 전달합니다.
result = parallel.invoke("LangChain")

# 각 branch 이름으로 결과를 읽습니다.
print(result["upper"])
print(result["length"])
print(type(result).__name__)
```

```python
# RunnablePassthrough.assign 예제
# RunnableLambda와 RunnablePassthrough를 가져옵니다.
from langchain_core.runnables import RunnableLambda, RunnablePassthrough


# 입력 딕셔너리의 question을 정리하는 함수를 정의합니다.
def extract_clean_question(data: dict) -> str:
    # 원본 문자열의 앞뒤 공백을 제거해 반환합니다.
    return data["question"].strip()


# 기존 입력을 유지하면서 clean_question 필드를 추가하는 단계를 만듭니다.
add_clean_question = RunnablePassthrough.assign(
    clean_question=RunnableLambda(extract_clean_question)
)

# 원본 질문과 수준이 있는 딕셔너리를 준비합니다.
input_data = {
    "question": "  Runnable이란 무엇인가요?  ",
    "student_level": "입문",
}

# assign 단계를 실행해 필드가 추가된 새 결과를 받습니다.
result = add_clean_question.invoke(input_data)

# 앞뒤 공백이 보이도록 기존 question을 세로선 사이에 출력합니다.
print(f"|{result['question']}|")

# 기존 student_level이 유지되었는지 확인합니다.
print(result["student_level"])

# 새 clean_question이 추가되었는지 확인합니다.
print(result["clean_question"])
```

## 헷갈렸던 부분 & 해결
- `StrOutputParser()`의 결과가 문자열로 나온다고 생각했는데, 직접 확인해보니 순수 문자열이 아니라 문자열을 상속한 클래스가 출력되는 거였고, 동작 자체는 문자열과 동일하게 한다는걸 확인했다.
- RunnableParallel의 동작 방식, RunnablePassthrough의 동작 방식에 대해서 조금 헷갈리는 부분이 있었는데, 계속해서 찾다보니까 큰 문제 없이 사용할 수 있는 수준이되었다.
