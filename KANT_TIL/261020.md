- 그 후에 모든 후보가 만들어지면 청크 사이즈 이내로 조합해서 최종 청크를 만든다.

- 이 경우에는 일반 문자열을 기준으로 한 것과 결과가 다를 수 있다.
- `MarkdownHeaderTextSplitter`를 통해서 마크다운 형식의 문서를 헤더를 기준으로 파싱할 수 있다.
- 헤더와 문자열 쌍의 튜플은 헤더를 기준으로 분리를 하며 문자열이 메타데이터에 키 값으로 밸류는 헤더의 이름이 된다.
- `SentenceTransformer`는 문자열을 고정 길이 벡터 공간에 임베딩하는데 쓰인다.
- `intfloat/multilingual-e5-small`임베딩 모델은 긴 문서와 짧은 질문을 효과적으로 매칭할 수 있도록 둘이 서로 다른 방식으로 임베딩하도록 만들어졌다.
- 그래서 문서에는 `passage: `를 붙이고, 질문에는 `query: `가 붙는다.
- Hit@k는 검색된 상위 k개의 청크 안에 정답 문서가 하나라도 들어 있는가를 측정하는 지표이다.
- recall@k는 검색된 상위 k개의 청크 안에 정답 문서를 얼마나 맞췄는지에 대해서 비율로 계산하는 지표이다.
- 현업에서는 베이스를 고를 때 소타를 기준으로 한다고 한다.

## 왜 중요한가
- RAG에 대한 전체적인 과정을 구성하는 요소들이기 때문에 매우 중요하다.
- 이걸 전부 외워서 작성할 필요는 없어도 구성을 이해하고 필요한걸 찾아서 사용할 필요는 있어야 할거 같다.

## 코드/예시
```python
# 윈도우 분리해내는 함수
def windows(text, size, overlap):
    result = []
    # 이동 간격은 size - overlap이에요. 80자와 겹침 20자라면 시작점이 0, 60, 120으로 이동해요.
    for start in range(0, len(text), size - overlap):
        # 마지막 구간이 원문 길이를 넘지 않게 end를 제한해요.
        # 반환값은 시작 위치, 끝 위치, 실제 본문이며 끝 위치는 슬라이스에 포함되지 않아요.
        end = min(start + size, len(text))
        result.append((start, end, text[start:end]))
        if end == len(text):
            break
    return result
```
