- 데이터 수집 & API 서버 구축5-2
  - path parameter는 대상 자원을 지정하는 변수이다.
  - query parameter는 대상 자원을 보고자 하는 방식에 대한 변수이다.
  - query parameter는 `fastapi.Query`를 통해서 지정할 수 있고, `default`, `ge`, `le`를 설정할 수 있다.
    - `default`: 기본값
    - `ge`: 최솟값
    - `le`: 최댓값
  - 지정된 범위를 넘어서는 값은 422오류를 발생시킬 수 있다.
  - request body는 json의 형태로 여러 필드의 데이터를 받을 때 사용한다.
  - 주로 경로에 넣기 적절하지 않거나 너저분해지는 것을 방지하는데 쓰인다.
  - `pydantic.BaseModel`를 상속한 클래스를 만들어서 구현한다.
  - 필드로 들어온 값들은 자동으로 클래스를 만들어서 함수 안에서 사용 가능하다.
  - 단, 초과되는 필드는 기본적으로는 무시하며, 부족한 필드는 오류를 일으킨다.
- 데이터 수집 & API 서버 구축6-1
  - pydantic은 필드와 함께 조건도 함께 선언이 가능하다.
  - 이를 스키마로써 정의하고 관리한다.
  - 각 필드에 데이터타입을 지정하면 그 전달받는 데이터가 해당한 타입이기를 기대하고 다르면 검증에 실패하게 된다.
  - 기본적으로 BaseModel에서 정의된 필드는 따로 설정한 것이 없다면 필수 필드이다.
  - `model_dump()`를 통해서 모델 객체를 딕셔너리로 변환할 수 있다.
  - `pydantic.Field`를 통해서 필드의 다양한 설정을 지정할 수 있다.
  - 길이나 필드에 대한 설명, 기본값 등을 설정할 수 있다.
  - default나 default_factory를 통해서 body request에 생략할 수 있는 필드를 설정할 수 있다.
  - default는 기본값이고, default_factory는 기본값인데, 리스트나 딕셔너리 같은 값의 기본값을 지정할 때 사용된다.
  - 만약 이걸 사용하지 않고 일반 default를 사용하는 경우에는 모든 요청들이 하나의 리스트 또는 딕셔너리를 공유하게 된다.
  - `max_length`같은 값은 문자열 말고도 리스트의 길이에 대해서 지정할 수 있으며, 한 번에 관리하기 위해서는 `Annoted`를 사용해야 한다.
  - 요청 모델에는 클라이언트가 보낸 값만이 들어간다.
  - 응답 모델은 사용자가 보낸 값을 포함하면서 서버의 값을 넣어서 하나의 객체를 만든다.
  - 함수의 반환값으로 응답 모델을 지정할 수 있음에도 api 데코레이터에서 응답 모델을 지정하는 이유는 파이썬 타입 힌트는 강제가 아니며, 문서화되지 않기 때문이다.
  - 또한 데코레이터에 지정된 응답 모델은 응답을 하면서 검사를 하게 되어 무결성이 보장된다.
  - 검증 오류 발생 시에 위치는 `loc`로 찾으면 location의 약자다.
