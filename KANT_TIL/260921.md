  - 그리고 질문에는 값이 자주 바뀌는지, 앞뒤 설명이 필요한지, 과거와 비교해야하는지를 표시한다.
  - 수집 경로는 데이터를 어디에서 어떻게 받는지에 대한 정보이다.
  - 데이터 형식은 받은 데이터가 어떤 구조로 표현되었는지에 대한 정보다.
    - 형식의 예에는 CSV, JSON, HTML, PDF 등이 있다.
  - 다섯 가지 수집 후보
    - 정적 파일: 기관이 특정 시점의 전체 자료를 파일로 배포하는 방식
    - CSV/JSON
    - 공공데이터 API: 공공기관이 정해 둔 유청 규칙으로 데이터를 조회하는 방식
    - 외부 서비스 API: 민간 서비스가 제공하는 지도, 번역, 검색 등의 API
    - 웹 데이터 수집: 웹페이지의 HTML에서 본문이나 표를 읽어오는 방식
  - 갱신 주기는 데이터가 새 값으로 바뀌는 간격이다.
  - 값이 자주 바뀐다고 해서 무조건 API를 사용해야 하는 것은 아니다.
  - 수집 비용은 데이터를 수집하는데 드는 비용으로 꼭 API 요금만을 뜻하지는 않는다.
    - 활용 신청과 승인에 드는 시간
    - 데이터를 정리하고 오류를 확인하는 시간
    - 웹 구조 변경에 대응하는 유지보수 시간
    - 호출 실패를 재시도하는 비용
    - 저장 공간과 백업 비용
  - 단순한 경로 원칙은 다음과 같다.
    - 구조가 더 명확한 것
    - 이용 조건이 더 분명한 것
    - 갱신 시점을 확인할 수 있는 것
    - 다시 내려받거나 보관하기 쉬운 것
  - 주기적 스냅샷은 특정 시점의 응답을 파일로 남기는 것이다.
  - 선택 기준표는 정답표가 아니라 근거를 보이게하는 표이다.

| 저장해도 되는가?      | 개인정보/보관 조건과 맞는가?            |
| 가공/공유해도 되는가? | 라이선스와 사용 목적에 맞는가?          |
  - 확인해야 하는 안정적인 경로
    - 공식 다운로드 파일
    - 공식 공공데이터 API
    - 공식 외부 서비스 API
    - RSS나 공개 피드
  - 5단계 위험 게이트
    - 이용약관: 자동 수집 허용 여부, 목적/재사용/재배포 계정, 계약 조건 - 모르면 보류
    - robots.txt: User-agent별 경로, Allow/Disallow, 웹 자동 수집일 때만 - 허가능 아님
    - 개인정보: 공개 여부와 무관한 식별성, 목적/최소 수집, 보유/삭제/접근 - 고위험은 전문 검토
    - 저작권, 라이선서: 원문 복제/변형, 상업적 이용, 출처표시/재배포 - 표시를 개별 확인
    - 접근, 부하: 로그인/유료벽 우회 금지, 요청 간격/중단 기준, 담당자 연락/승인 기록 - 서버 부담 최소화
  - 이용약관은 서비스 이용자와 제공자 사이의 규칙을 설명한다.
  - 핵심 단어
    - 자동, 로봇, 크롤링, 스크래핑
    - 복제, 저장, 다운로드
    - 가공, 2차적 이용
    - 재배포, 상업적 이용
    - 호출 제한, rate limit
    - 계정 공유, API 키
  - robots.txt는 웹 크롤러가 어떤 경로를 가져갈 수 있는지 알리는 규칙파일이다.
  - 보통 최상위 경로에 위치해있다.
  - 개인정보는 여러 정보가 결합되어 개인을 식별할 수 있다면 주의가 필요하다.
  - 입문자는 공개된 개인 연락처를 대량으로 모으거나, 원래 목적과 다른 용도로 개인 정보를 사용하려 하거나, 필요한 기간과 삭제 기준을 설명할 수 없거나, 개인을 알아볼 필요가 없는데 식별자를 그대로 저장하거나, 민감한 내용이 포함될 수 있을 때 멈춰야 한다.
  - 개인정보와 관련해서는 꼭 목적에 필요한 필드만을 수집한다.
  - 나중에 쓸지 모른다는 이유로 모든 필드를 저장해서는 안된다.
  - 웹에서 무료로 볼 수 있다고 해서 자유롭게 복제/가공/배포할 수 있다는 것은 아니며, 다음을 확인해야 한다.
    - 콘텐츠의 제작자는 누구인가?
    - 권리자는 누구인가?
    - 어떤 라이선스가 표시되어 있는가?
    - 출처 표시나 변경 표시 조건은 무엇인가?
    - 우리가 하려는 저장/가공/제공과 조건이 맞는가?
  - 라이선스 표시가 있을 때에는 라이선스 이름만 적지 말고 버전과 원본 URL을 기록한다.
  - 라이선스 표시가 없다면 자유 이용이라는 것이 아니고, 권리자에게 문의를 하는 것이 좋다.
  - 기관 페이지 안의 사진이나 도표가 외부 제작자의 자료일 수 있기 때문에 페이지 전체 정책만 볼 것이 아니라 credit, rights 표시도 함께 확인한다.
  - 가능/주의/제외 판단표는 확인한 사실을 빠르게 비교하는 도구이다.
    - 후보, 약관, robots.txt, 개인정보, 재사용 조건, 상태 등의 정보를 가질 수 있다.
  - 상태의 의미

|------|----------------------------------------------|-------------------------|

| 주의 | 확인하지 못한 항목이나 조건이 있음           | 문의/검토 후 재판단     |
| 제외 | 목적상 불필요한 개인정보 등 뚜렷한 중단 사유 | 수집하지 않고 대안 탐색 |

## 왜 중요한가
- 정보를 수집하는 과정에서부터 수집 시에 주의해야하는 점까지에 대한 내용이기 때문에 중요하다.
- 사실 수집하는 행위 자체는 그렇게 어렵지 않다.
- 그러나 어느 경우에 해서는 안되는지에 대해서 생각하는건 쉽지 않기 때문에 중요한 내용이었다고 생각한다.

## 코드/예시
```python
# 간단한 파이썬 요청 보내기
import httpx


# with 블록을 벗어나면 연결 자원이 자동으로 정리됩니다.
with httpx.Client(base_url="https://api.example.org/v1") as client:
    print(client.base_url)

# 실제 요청 코드는 다음 절에서 headers와 params를 함께 전달합니다.
endpoint = "/news"
print(endpoint)

api_key = "환경 변수에서 읽은 값"

# 인증 header 이름은 반드시 실제 API 문서의 표기를 따릅니다.
headers = {
    "X-API-Key": api_key,
    "Accept": "application/json",
}

# 문자열로 URL을 이어 붙이지 않고 이름과 값을 딕셔너리에 담습니다.
params = {
    "q": "데이터",
    "limit": 2,
}

# 요청은 Client가 열려 있는 with 블록 안에서 보냅니다.
with httpx.Client(base_url="https://api.example.org/v1", timeout=5.0) as client:
    response = client.get(
        "/news",
        headers=headers,
        params=params,
    )
```
